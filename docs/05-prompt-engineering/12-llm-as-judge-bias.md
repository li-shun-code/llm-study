"让 GPT 来打分"已经是今天做提示词迭代、模型选型、回归测试最常见的手段。它确实省钱，但它不是无偏的量尺：评审模型会偏爱**排在某个位置的答案**、偏爱**写得更长的答案**、偏爱**自己家模型写的 answer**，还会在需要算术与事实核验时判错。这篇给出偏差的可跑测量方法与校准手段——把"用 LLM 评审"从一句话变成一套有置信度的流程。

## 三种判法，各有适用面

Zheng et al. (2023) 在提出 MT-Bench 与 Chatbot Arena 时，把 LLM-as-a-Judge 拆成三种可独立或组合使用的形态：

1. **两两比较（pairwise comparison）**：给问题与 A/B 两个回答，判谁更好或平局。缺点是可扩展性差——n 个候选要跑 O(n²) 对。
2. **单答案打分（single answer grading）**：让评审按量表（如 1–10）给一个回答打分，可扩展、便于做版本回归；缺点是对量表口径极敏感，且不同批次的分数不一定可比。
3. **参考引导打分（reference-guided grading）**：把参考答案一起交给评审（论文在数学题上就是这么用的），显著改善事实性判断——代价是你得先有参考答案。

论文的核心验证是：**强评审模型（GPT-4）与人类偏好的一致率超过 80%，与"人与人之间的一致率"同一水平**（3K 条受控专家投票 + 3K 条众包投票）。这句话常被引用成"LLM 评审可信"，但同一段摘要里同样明确的另一半是：**存在位置偏置、冗长偏置、自我增强偏置，以及有限的推理能力**。可信度是校准之后的结论，不是默认属性。

## 四类偏差与它们的成因

- **位置偏置（position bias）**：同一对答案换顺序，结论就变。论文举的例子是 GPT-4 先看 GPT-3.5 的回答，认为它"更详细、更好"；交换位置后却转而偏好 Vicuna 的回答。成因很朴素：A/B 只是**渲染顺序**，不是属性，而模型的注意力会被先出现的那段文本锚定。
- **冗长偏置（verbosity bias）**：长度本身被当成质量信号。工程上最阴险，因为"更详细"和"更好"在人评里也经常被混淆，回归测试一旦改成"新版本写得更长"就会自动涨分。
- **自我增强偏置（self-enhancement bias）**：模型偏好与自己同源、同风格的输出。做"用同一个模型既生成又打分"的自动优化时，这条会把提示词推向"讨好评审"的方向，而不是推向真实质量。
- **推理能力有限（limited reasoning ability）**：涉及算术、代码执行结果、事实核验时，评审模型自己就会算错；这类判定应该交给执行器（跑测试、跑计算器、比对参考解），而不是交给语言建模。

论文给的处理思路是：**双序一致才算判出胜负**（不一致记为 tie）、必要时引入参考解、以及用"先给评审理由再给分数"的方式提升可解释性；并指出有些偏差量级很小、可以缓解，有些无法根除。

## 可跑：一次测出你自己那套评审的偏差

下面脚本不需要人工标注，直接量三类偏差。运行前置 `pip install openai python-dotenv`：

```python
"""LLM-as-Judge 三类偏差的最小测量：位置、冗长、自我偏好。"""
import os
import re
import statistics
import time

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI()
MODEL = os.getenv("OPENAI_MODEL", "gpt-5.4-mini")          # 同时充当"被评审模型的兄弟"

PAIRS = [
    ("用一句话说明什么是幂等性（idempotency）。",
     "同一操作执行多次与执行一次产生的效果相同。",
     "幂等性指同一操作重复执行一次与多次，对系统状态的影响相同；例如 HTTP PUT 是幂等的，POST 不是。"),
    ("为什么 API 分页要返回游标而不是页码？",
     "游标能避免翻页时因数据增删导致的漏读与重复读。",
     "页码依赖快照式偏移量，翻页间隙发生插入/删除时同一条记录可能被跳过或重复；游标锚定在上一条已读记录上，因而更稳。"),
    ("什么是连接池？",
     "复用已建立的连接，减少反复握手的开销。",
     "连接池维护一组可复用的已建立连接，请求到来时借出、结束后归还，从而把三次握手与 TLS 协商的成本摊薄。"),
]

JUDGE_SYS = ("你是严格的评审。给定问题与两个回答 A、B，判断哪个更好。"
             "只输出一行：裁决为 A / B / tie 之一，并给出 5 个词以内的理由。")


def ask(prompt: str, system: str = JUDGE_SYS) -> str:
    for attempt in range(5):                        # 并发或限流时最简退避
        try:
            r = client.responses.create(
                model=MODEL,
                input=[{"role": "system", "content": system}, {"role": "user", "content": prompt}],
                max_output_tokens=800,
            )
            return r.output_text.strip()
        except Exception:
            time.sleep(5 * (attempt + 1))
    raise RuntimeError("连续失败")


def verdict(text: str) -> str:
    m = re.search(r"\b(A|B|tie)\b", text, re.I)
    return m.group(1).upper() if m else "?"


def chosen(question: str, first: str, second: str) -> tuple[str, str]:
    """返回（被选中那条答案的"身份证"=前 12 字, 评审原话）。

    用内容而不是 A/B 标签来记账，才能把"换了顺序"和"换了结论"区分开。
    """
    raw = ask(f"问题：{question}\nA：{first}\nB：{second}\n请裁决。")
    v = verdict(raw)
    return {"A": first[:12], "B": second[:12]}.get(v, "tie"), raw


def score(question: str, answer: str, source: str) -> float:
    """单答案打分（1-10），用于自我偏好实验。"""
    raw = ask(f"问题：{question}\n回答（来自 {source}）：{answer}\n按 1-10 打质量分，只输出数字。",
              system="你是严格的质量评审，按 1-10 打分，10 表示完美。")
    m = re.search(r"(\d+(?:\.\d+)?)", raw)
    return float(m.group(1)) if m else float("nan")


if __name__ == "__main__":
    print("== 位置偏置：换顺序，看选中的内容会不会跟着换")
    flips = 0
    for q, a, b in PAIRS:
        (c1, _), (c2, _) = chosen(q, a, b), chosen(q, b, a)      # 第二次把 b 放到 A 位
        flip = c1 != c2
        flips += flip
        print(f"  正序={c1!r} 反序={c2!r} {'翻转（位置偏置）✗' if flip else '一致 ✓'}")
    print(f"  翻转率 {flips}/{len(PAIRS)}\n")

    print("== 冗长偏置：同一份内容，只把 B 灌水加长（问题明确要求'一句话'）")
    SHORT = "同一操作执行多次与执行一次效果相同。"
    LONG = ("这是一个非常重要的概念，在分布式系统与 API 设计中被反复强调，很多教科书都讨论过："
            "所谓幂等性，指同一目标操作执行多次与执行一次的最终效果完全相同；HTTP 语义里 PUT 与 DELETE "
            "通常被视为幂等，POST 不是；重试策略与消息投递语义都会与它关联，实际项目还要考虑去重表与幂等键。")
    q = "用一句话说明什么是幂等性（idempotency）。"
    for i in range(3):
        pick, raw = chosen(q, SHORT, LONG)
        print(f"  第 {i + 1} 次：选了 {pick!r}（{raw[:40]}）")

    print("\n== 自我偏好：同一段回答，只改来源标签")
    q, answer = PAIRS[1][0], PAIRS[1][2]
    for src in (MODEL, "claude-sonnet-5"):                        # 第一个标签就是评审模型自己
        vals = [score(q, answer, src) for _ in range(2)]
        print(f"  标注 {'<与评审同源>' if src == MODEL else src:12s} -> {vals}，均值 {statistics.mean(vals):.1f}")
```

本机实测（第一遍）：

```
== 位置偏置
  正序='同一操作执行多次与执行一' 反序='同一操作执行多次与执行一' 一致 ✓
  正序='页码依赖快照式偏移量，翻' 反序='页码依赖快照式偏移量，翻' 一致 ✓
  正序='连接池维护一组可复用的已' 反序='连接池维护一组可复用的已' 一致 ✓
  翻转率 0/3

== 冗长偏置（问题要求"一句话"）
  第 1 次：选了 '同一操作执行多次与执行一'（A，简洁符合"一句话"要求。）
  第 2 次：选了 '同一操作执行多次与执行一'（A，回答简洁切题。）
  第 3 次：选了 '同一操作执行多次与执行一'（A，一句话精准回答。）

== 自我偏好（同一段回答，只改来源标签）
  标注 <与评审同源>    -> [8.0, 8.0]，均值 8.0
  标注 claude-sonnet-5 -> [nan, 8.0]，均值 nan
```

两遍运行合起来看，位置实验的另一遍给出过 `翻转率 1/2`（一次把长答判定为平局）；两遍都一致的结论是"0 翻转 ≠ 没有位置偏置"。

那个 `nan` 不是刻意留的 bug 演示，而是**这条流水线真实会坏的地方**：评审偶尔不按"只输出数字"回答（回了一句中文评语），抽取器拿不到分数就返回 NaN。把它当 0 分或悄悄丢掉，统计就会偏；正确做法是把"抽取失败率"当成一等指标监控，并在提示与解析两处同时收紧。同一段实验的另一次运行是 `标注 <与评审同源> -> [9.0, 8.0]，均值 8.5` / `标注 claude-sonnet-5 -> [8.0, 8.0]，均值 8.0`，也就是 +0.5 的差；这次则是 0 分差加一次抽取失败。

这组数字里至少有三条能迁移到你的项目：


1. **位置偏置在 3 对样本上是 0/3，但同一段代码换一轮跑出 1/2**——这类偏差的测量本身噪声很大，跑 3 对就宣布"我的评审没有位置偏置"是没有意义的。论文用 3K 级别样本得到的结论才站得住。
2. **冗长偏置被压住了，因为提示里写了"一句话"**：任务里明确的可判定标准，能显著改变评审的关注点。这提示校准的第一杠杆不是换模型，而是**把评分维度写清楚**。
3. **自我偏好两次运行给出不同答案**（一次 +0.5、一次 0 分差外加一次抽取失败）：这正是最常见的错误做法——用每组 2 次运行的结果下结论。正确姿势是配对设计：同一段回答两种标签、各跑 n≥30 次，报配对差值与置信区间，并同时报告抽取失败率。

## 校准：五件可立刻执行的事

**1. 双序一致才判胜负。** 交换 A/B 各跑一次，两次结论一致才记为胜负，否则记 tie。论文用它缓解位置偏置，实现只要十行。

**2. 输出结构化 + 强制"先理由后分数"。** 用 JSON/Pydantic 固定裁决字段与理由字段（见《JSON Mode 与结构化输出（Structured Outputs）》），既方便统计，也减少理由与分数不匹配的情况。

**3. 能用规则就别用评审。** 格式、字段、能否编译、测试是否通过、数值是否相等——先跑确定性的检查；把语言模型只留给"内容质量"这种真需要判断的部分。

**4. 与人评对齐之后再上线。** 拿 50–100 条人工标注做标定，报一致率与 Cohen's kappa：

```python
"""评审校准的最小统计：一致率与 Cohen's kappa（只用标准库）。"""


def agreement_and_kappa(a: list[str], b: list[str]) -> tuple[float, float]:
    """两个评审（或评审与人工）对同一批样本的标签一致性。"""
    n = len(a)
    po = sum(x == y for x, y in zip(a, b)) / n                        # 观察一致率
    pe = sum((a.count(l) / n) * (b.count(l) / n) for l in set(a) | set(b))   # 期望一致率
    return po, (po - pe) / (1 - pe) if pe < 1 else 1.0


if __name__ == "__main__":
    human = ["A", "B", "tie", "A", "B", "A", "tie", "B", "A", "B"]
    judge_raw = ["B", "B", "tie", "B", "B", "B", "tie", "B", "B", "B"]   # 未校准：一半结论塌向 B
    judge_cal = ["A", "B", "tie", "A", "B", "A", "tie", "B", "A", "tie"]  # 加了双序一致 + rubric
    for name, j in (("未校准", judge_raw), ("校准后", judge_cal)):
        po, k = agreement_and_kappa(human, j)
        print(f"{name}: 一致率 {po:.2f}  kappa {k:.2f}")
```

本机输出：`未校准: 一致率 0.60  kappa 0.37` / `校准后: 一致率 0.90  kappa 0.85`（这两行是**构造出来的示意数据**，用来演示两种指标为什么会分叉：一致率 0.60 看着"还行"，kappa 0.37 说明剔除随机一致后几乎没有真实一致性。你自己的数据要用真实标注。）

**5. 别让评审模型与生成模型同源自评。** 至少做两件事：用不同家族模型做评审，以及在关键决策上抽样人评复核。提示词自动优化（把评审分数当奖励去改提示）时尤其重要，否则很容易把提示词优化成"讨好这个评审"。

## 常见坑

- **只报平均分不报方差与 n**：单答案打分的量表漂移很大，同一条回答换个批次可能差 1–2 分。
- **把 tie 当失败**：双序一致流程里 tie 是有效信息（说明这道题不该由语言模型判，或两条确实等价）。
- **量表里混维度**：一个分数同时代表"事实性 + 结构 + 语气"，等于什么都没测。拆成多维度分别打分。
- **让评审看到元数据**：模型名、字数、来源标签都会成为偏置入口。本文的自我偏好实验正是只改标签就改变了分数走向。
- **用长上下文喂一整批评测**：评审的注意力同样会腐烂，逐条（或小批）调用比一次塞 50 条稳定得多（见《上下文工程：为 AI Agent 管理稀缺的注意力》）。

## 小结

- LLM 评审可达到的与人同级的一致率（论文 >80%），但前提是**校准过**；
- 已知偏差：位置、冗长、自我增强、推理能力有限；前两个可用"双序一致 + 明确量表"压，第三个靠异构评审与人评抽样；
- 偏差要**测**：翻转率、配对差、一致率/kappa，都是几行代码的事；样本量不够的结论等于没有结论；
- 事实与格式判定交给执行器，语言模型只判"需要判断的部分"。
