Linux 这类类 Unix 操作系统与其他计算系统的一大区别：它们不仅是**多任务**（multitasking）的，还是**多用户**（multi-user）的。

这是什么意思？意思是多个用户可以同时使用这台计算机。即便一台台式机/笔记本只有一套键盘和显示器，它也可能被不止一个用户使用：比如计算机接入网络后，远程用户可以通过 `ssh`（secure shell，安全外壳协议）登录并操作它——远程用户甚至可以执行图形程序、让输出显示在远程计算机上，X Window 系统就支持这一点。

类 Unix 系统的多用户能力深深植根于操作系统设计。想想 Unix 诞生的年代背景就顺理成章：在计算机还不是"个人"电脑的岁月里，计算机又大又贵又集中。一所典型的大学计算机系统，是放在某栋楼里的大型主机，加上散布校园各处的**终端**（terminal），每台终端都连着中央大机器——一台计算机同时服务许多用户。

要让这件事切实可行，就必须设计出让用户彼此隔离的机制：我们既不希望一个用户的操作弄崩计算机，也不允许一个用户动另一个用户的文件。

本篇将覆盖以下命令：

- `chmod` —— 修改文件的访问权限
- `su` —— 临时成为超级用户
- `sudo` —— 临时成为超级用户
- `chown` —— 更改文件所有者
- `chgrp` —— 更改文件的属组

## 文件权限

在 Linux 系统上，每个文件和目录都针对三类主体分配了访问权限：文件的**所有者**（owner）、一组相关用户构成的**组**（group），以及**其他人**（everybody else）。权限包括：读文件、写文件、执行文件（即把文件当作程序运行）。

用 `ls` 命令可以查看文件的权限设置。以 `/bin` 目录下的 `bash` 程序为例：

```
[me@linuxbox me]$ ls -l /bin/bash
-rwxr-xr-x 1 root root 1113504 Jun  6  2019 /bin/bash
```

从这里可以看出：

- 文件 `/bin/bash` 的所有者是用户 `root`
- 超级用户对该文件拥有读、写、执行三种权限
- 该文件属于 `root` 组
- `root` 组的成员可以读和执行该文件
- 其他所有人也可以读和执行该文件

列表开头的第一个字符表示文件类型；随后三组、每组三个字符，依次表示所有者、组、其他人的读/写/执行权限：

```
- rwx r-x r-x
│  │   │   └─ 其他人：读、执行
│  │   └───── 组：读、执行
│  └───────── 所有者：读、写、执行
└──────────── 文件类型（- 普通文件，d 目录）
```

## chmod

`chmod` 命令用于修改文件或目录的权限。使用时要给出目标权限设置和要修改的文件。指定权限有两种写法，本篇聚焦其中之一：**八进制记法**（octal notation）。

把权限设置想成一串比特（计算机正是这么看它们的），就很好理解：

```
rwx rwx rwx = 111 111 111
rw- rw- rw- = 110 110 110
rwx --- --- = 111 000 000
```

每一组三位二进制对应一个八进制数字：

```
rwx = 111 (二进制) = 7
rw- = 110 (二进制) = 6
r-x = 101 (二进制) = 5
r-- = 100 (二进制) = 4
```

于是，把所有者/组/其他人三组权限各用一位数字表示，就能非常简洁地表达各种权限组合。例如，想让 `some_file` 只有所有者可读写、其他人完全不可见：

```
[me@linuxbox me]$ chmod 600 some_file
```

下面是常见设置的速查表。以 7 开头的设置通常用于程序（因为开启了执行权限），其余用于一般文件：

| 值 | 含义 |
|---|---|
| **777** | `(rwxrwxrwx)` 权限完全放开，任何人可以做任何事。一般不是理想设置。 |
| **755** | `(rwxr-xr-x)` 所有者可读、写、执行；其他人可读和执行。对所有用户共用的程序而言是常见设置。 |
| **700** | `(rwx------)` 所有者可读、写、执行；其他人毫无权限。适合只有所有者使用、需对他人保密的程序。 |
| **666** | `(rw-rw-rw-)` 所有用户都可读写该文件。 |
| **644** | `(rw-r--r--)` 所有者可读写，其他人只读。人人可读、仅所有者可改的数据文件的常见设置。 |
| **600** | `(rw-------)` 所有者可读写，其他人毫无权限。所有者想保密的数据文件的常见设置。 |

> 译注：本模块第一篇（Missing Semester 讲义）还介绍了符号记法（如 `chmod +x file`）以及 u/g/o/a 的用法，两种写法可配合使用。

## 目录权限

`chmod` 同样可以控制目录的访问权限，也能用八进制记法，但 r、w、x 的含义有所不同：

- **r** —— 在 x 也已设置的前提下，允许列出目录内容。
- **w** —— 在 x 也已设置的前提下，允许在目录内创建、删除、重命名文件。
- **x** —— 允许进入目录（即 `cd dir`）。

目录的常用设置如下：

| 值 | 含义 |
|---|---|
| **777** | `(rwxrwxrwx)` 完全放开：任何人可列目录、在其中创建与删除文件。一般不是好设置。 |
| **755** | `(rwxr-xr-x)` 目录所有者全权；其他人可列出目录但不能创建或删除文件。想与他人共享的目录常用此设置。 |
| **700** | `(rwx------)` 目录所有者全权；其他人毫无权限。只有所有者使用且需保密的目录适用。 |

## 临时成为超级用户

执行重要的系统管理任务时常需要超级用户身份，但我们已经知道不应长期以超级用户登录。多数发行版都提供了临时借用超级用户权限的程序。`su`（substitute user 的缩写）可用于少量任务需要超级用户的场合。想成为超级用户，直接输入 `su`，随后输入超级用户密码：

```
[me@linuxbox me]$ su
Password:
[root@linuxbox me]#
```

执行 `su` 后，你会得到一个以超级用户运行的新 Shell 会话；输入 `exit` 即可退出并回到原会话。

许多现代发行版改用另一种方式：不用 `su`，而用 `sudo`。`sudo` 让一个或多个用户按需获得超级用户权限：在需要的命令前加 `sudo` 即可。命令执行时要求输入的是**你自己的**密码，而不是超级用户的：

```
[me@linuxbox me]$ sudo some_command
Password for me:
[me@linuxbox me]$
```

事实上，一些现代发行版干脆不给 root 账户设置密码，使直接以 root 登录变得不可能。仍可用 `sudo` 的 `-i` 选项获得 root Shell：

```
[me@linuxbox me]$ sudo -i
Password for me:
root@linuxbox:~#
```

## 更改文件所有者

用 `chown` 命令可以更改文件的所有者。例如把 `some_file` 的所有者从 "me" 改为 "you"：

```
[me@linuxbox me]$ sudo chown you some_file
```

注意：更改文件所有者需要超级用户权限，所以示例里用 `sudo` 执行了 `chown`。`chown` 对目录和对文件的用法一致。

## 更改属组

文件或目录的属组可以用 `chgrp` 更改：

```
[me@linuxbox me]$ chgrp new_group some_file
```

上例把 `some_file` 的属组从原先的组改为 "new_group"。执行 `chgrp` 必须是文件或目录的所有者。
