基础模型（Foundation Model）不仅"被困在过去"，还会刻意生成听起来自然、富有变化的回答。这两点叠加，就会产生自信却错误、且不相关的内容——这就是所谓的"幻觉（Hallucination）"。

本文将介绍基础模型的局限性，以及检索增强生成（Retrieval-Augmented Generation，RAG）如何解决这些局限，让聊天、搜索和智能体（Agent）工作流都从中受益。

## 基础模型的局限

完全构建在基础模型之上的产品"聪明但有缺陷"，因为基础模型存在多个先天限制：

### 知识截止（Knowledge Cutoff）

当你问当前模型最近的事件——比如上周的 NBA 比赛，或者最新款 iPhone 的功能怎么用——它可能自信地给出过时的、甚至完全捏造的答案，也就是前面提到的幻觉。

模型在包含数年人类知识与创作产出的海量数据集上训练：代码仓库、书籍、网站、对话、科学论文等。但训练完成后，这些数据就被冻结在某个时间点，即"截止时间（cutoff）"。截止时间造成了**知识鸿沟**：当被问及最新动态时，模型会生成看似合理却错误的回答。

### 缺乏领域深度知识

基础模型知识面广，但在专门领域可能缺乏深度。某个领域可能没有公开的高质量数据集——不一定因为是私有数据，而是因为高度专业化。想象一个医学模型：它了解解剖学、疾病和外科技术，却对罕见遗传病和前沿疗法束手无策。这些数据或许公开存在，但数量可能不足以让模型正确学到，而且训练过程中还需要专家级知识来为信息建立语境。

这一限制会导致回答不完整或不相关。

### 缺乏私有/专有数据

对于通用公开模型而言，你的数据并不公开，训练时无法访问。这意味着模型不了解你业务的具体情况：公司内部流程与制度、人事数据、邮件往来，乃至商业机密。而且这有充分的理由：如果这些数据被纳入训练，任何使用该模型的人都可能获取你公司的私有数据。

同样，这一限制会导致回答不完整或不相关，让模型难以胜任你的定制业务场景。

### 失去信任

模型通常无法为某个具体回答给出信息来源。没有引用或出处，用户只能选择"信"或者自己花时间验证。考虑到模型在海量公开数据上训练，生成的回答有可能来自不权威的来源。

当模型持续生成不准确、不相关、无用的信息时，用户会失去对模型本身的信任——即使这些行为是基础模型的固有属性。

### 输出生成是概率性的

幻觉常常是上述局限的"症状"。但更根本地，模型训练数据五花八门，其中包含矛盾、错误和歧义（当然也有正确数据）。因此，模型会给所有可能的续写赋概率——包括错误的续写。由于 temperature、top-k 等采样随机性，加上用户构造提示词的方式（可能过于模糊或含误导性上下文），模型可能选中错误的续写，最终输出包含幻觉的内容。

此外，模型并不总能区分"自己知道"与"自己不知道"，即使回答不完整、不准确、不相关，语气也十分自信。幻觉可能造成不良后果，甚至危险：例如一份不准确却极具说服力的医疗报告，可能导致危及生命的治疗，或者干脆导致放弃治疗。

这些基础模型层面的局限会影响业务收益、侵蚀用户信任。检索增强生成正是用来解决这些局限的。

## 什么是检索增强生成？

检索增强生成（RAG）是一种利用权威外部数据来提升模型输出的准确性、相关性与有用性的技术。它由以下四个核心组件构成（后文将详细展开）：

1. **摄取（Ingestion）**：把公司专有数据等权威数据载入数据源，例如 Pinecone 向量数据库；
2. **检索（Retrieval）**：根据用户查询，从外部数据源检索相关数据；
3. **增强（Augmentation）**：把检索到的数据与用户查询合并成提示词（Prompt），为生成步骤提供上下文；
4. **生成（Generation）**：模型基于增强后的提示词生成输出，借助上下文给出更准确、更相关的回答。

**表：传统 RAG 四步流程**

| 阶段 | 做什么 |
| --- | --- |
| 摄取 | 清洗、分块、嵌入，把权威数据装入向量数据库 |
| 检索 | 用查询向量在库中做相似度搜索，取回相关内容 |
| 增强 | 检索结果 + 用户查询拼装成带上下文的提示词 |
| 生成 | LLM 基于上下文生成有依据的回答 |

把外部数据源中的相关数据与用户查询一起作为上下文提供给模型，模型就能据此生成更准确、更相关的输出。

RAG 带来以下收益：

1. **获得实时数据与专有/领域数据**：引入与你场景相关的知识——时事、新闻、社交媒体、客户数据、专有数据；
2. **建立信任**：更相关、更准确的结果更容易赢得信任，来源引用也便于人工复核；
3. **更多控制力**：控制使用哪些来源、实时数据访问、数据授权、护栏/安全/合规、可追溯性与来源引用、检索策略、成本，并且每个组件都可以独立调优；
4. **相比其他方案更省钱**：无论是训练/再训练自己的模型、微调（Fine-tuning），还是硬塞上下文窗口，成本都更高——基础模型的制作成本高昂且需要专业知识，微调亦然；发给模型的上下文越大，成本越高。

### RAG 支撑智能体工作流

传统 RAG 方案很简单：一个向量数据库加一个"一次成文"的带上下文提示词。而随着 AI 智能体（Agent）的兴起，Agent 成为 RAG 核心组件的**编排者（Orchestrator）**，它可以：

- 构造更有效的查询；
- 访问更多检索工具；
- 评估检索上下文的准确性与相关性；
- 通过推理验证检索到的信息，决定信任还是丢弃。

这些操作可以由一个或多个 Agent 作为更大迭代计划的一部分来执行。Agent 作为 RAG 的编排者，带来了更多审阅、查询改写、上下文推理与验证的机会，使其能做出更好的决策、采取更有依据的行动，生成更准确、更相关的输出。

下面深入拆解 RAG 的工作原理。

## RAG 是如何工作的？

RAG 依靠权威数据源（专有领域数据、实时信息）为 LLM 输出带来准确性与相关性。但在深入之前，先问两个问题：你真的需要 RAG 吗？你怎么知道它起作用了？

这就需要**真值评估（Ground Truth Evaluation）**。要正确上线任何应用，你得知道它什么时候是正常的。AI 应用也不例外：整理一组查询及其期望答案，是判断应用是否正常的关键；持续维护这组评估集，则是判断该往哪里改进、改进是否有效的关键。RAG 本身只是一种优化手段，其他手段还包括查询改写、分块扩展、知识图谱等等。

有了良好的基线，就可以动手实现 RAG 的四大组件了。

### 摄取（Ingestion）

在简单的传统 RAG 中，你会从 Pinecone 这样的向量数据库检索数据，用语义搜索（Semantic Search）理解用户查询的"真实含义"并取回相关信息，而不是简单匹配关键词。这里以 Pinecone 为例，但概念适用于所有向量数据库。

检索之前必须先摄取数据。把数据装进数据库的步骤如下：

#### 对数据分块（Chunk）

摄取阶段，你要把权威数据以向量的形式装进 Pinecone。数据可能是结构化或非结构化的：文本、PDF、邮件、内部 Wiki 或数据库。清洗数据后，通常需要"分块"——把每份数据（文档）切成更小的块。根据数据类型、用户的查询类型、以及结果在应用中的使用方式，你需要选择合适的分块策略（详见本模块《文档分块策略》一文）。

#### 创建向量嵌入（Embedding）

然后，用嵌入模型（Embedding Model）把每个块向量化并装入向量数据库。嵌入模型是一种特殊的 LLM，它把数据块转换成向量嵌入（Vector Embedding）——数据语义的数值表示。有了它，计算机就能基于语义相似度搜索数据。

#### 把数据装入向量数据库

有了向量，就装入向量数据库。这一步通常离线进行，与应用和用户工作流相互独立。但如果数据会变化——比如商品库存更新——你也可以实时更新索引，让用户始终拿到最新信息。

向量数据库装好源数据的向量嵌入后，就进入检索步骤。

### 检索（Retrieval）

最简单的检索只用语义搜索。但采用**混合搜索（Hybrid Search）**——把语义搜索（稠密向量）与词法搜索（稀疏向量）结合——检索效果可以进一步提升。当用户谈论同一主题时未必总用同一套词，还常会引用内部领域语言（缩写、产品名、团队名）时，混合检索尤其有用。

检索时，先把用户查询转成向量嵌入，再去数据库中搜索相似向量。混合搜索下，可以查单个混合索引，或同时查稠密与稀疏两个索引；随后合并去重，用重排序（Rerank）模型按统一相关性分数重新排序，返回最相关的结果。

### 增强（Augmentation）

拿到检索阶段的最相关结果后，把搜索结果与用户查询一起组装成增强提示词发给 LLM。奇迹就在这一步发生。

增强提示词大致长这样：

```text
QUESTION:
<用户的问题>

CONTEXT:
<用作上下文的搜索结果>

Using the CONTEXT provided, answer the QUESTION. Keep your answer grounded in the facts of the CONTEXT. If the CONTEXT doesn't contain the answer to the QUESTION, say you don't know.
```

把搜索结果与用户问题一起作为上下文发给 LLM，就是在引导它在下一步生成中优先使用搜索结果中更准确、更相关的信息。

### 生成（Generation）

有了增强提示词，LLM 就拿到了来自向量数据库的最相关、最有依据的事实，应用就能给出准确回答，降低幻觉概率。

但如今的 RAG 已经不只是"找到对的信息喂给模型"。在智能体 RAG（Agentic RAG）中，关键变成了：决定问什么问题、用哪些工具、何时使用，然后聚合结果为回答提供依据。

在这一简单版本里，LLM 就是那个智能体：它决定用哪些检索工具、何时使用、以及如何查询。

## 小结

检索增强生成已从流行词演变为 AI 应用不可或缺的基石。它把基础模型的广博能力与你公司的权威、专有知识结合起来。随着 AI 智能体承担更复杂的应用场景，RAG 不只是在当下重要——它是构建准确、相关、负责任的 AI 应用的关键，其意义超越信息检索本身。当智能体越来越自主、承担越来越复杂的工作流时，它们更需要通过 RAG 把推理锚定在你的私有与领域数据上。问题不再是"要不要做 RAG"，而是"如何为你的独特场景与数据需求，把它架构得最有效"。
