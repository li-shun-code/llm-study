向量嵌入（Vector Embedding）已被证明是自然语言处理、计算机视觉等多个领域的有效工具。比较嵌入、判断相似度，是语义搜索（Semantic Search）、推荐系统、异常检测等系统的核心环节——也是 RAG 检索步的本质。

选择相似度度量的**基本经验法则**：**与你嵌入模型训练时使用的度量保持一致**。例如 [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) 用余弦相似度训练——索引就该用余弦相似度，结果才最准确；模型若用欧氏距离训练，索引同样该用欧氏距离。

什么是"两个向量相似"？语境不同，答案不同：在自然语言处理中，若两个词向量常出现在相似语境、或关联相似概念，它们就"接近"；在推荐系统中，若两个用户偏好向量兴趣相同或曾做过相同选择，它们就相似。

**表：三种相似度度量与所考虑的向量属性**

| 相似度度量 | 考虑的向量属性 |
| --- | --- |
| 欧氏距离（Euclidean Distance） | 模长与方向 |
| 余弦相似度（Cosine Similarity） | 仅方向 |
| 点积相似度（Dot Product Similarity） | 模长与方向 |

## 欧氏距离（Euclidean Distance）

欧氏距离是两个向量在多维空间中的直线距离。对向量 **a** 和 **b**，先把对应分量逐一相减（a1−b1, a2−b2, …, an−bn），把各差值平方后求和，再开平方根：

```
d(a, b) = sqrt( (a1-b1)² + (a2-b2)² + ... + (an-bn)² )
```

这个度量对数值尺度与向量的相对位置都敏感：数值大的向量之间欧氏距离天然更大，即使它们在其他方面很相似。

欧氏距离是最"直白"的相似度度量——它字面意义上反映了两个向量各坐标值之间的距离：欧氏距离很小，就意味着各坐标都很接近。这一点对点积和余弦一般不成立。

深度学习嵌入模型通常不使用欧氏距离，它更多配合 LSH（Locality Sensitive Hashing，局部敏感哈希）等较基础的向量编码方法。一般而言，当模型训练时没有特定损失函数，欧氏距离是自然选择。由于它对模长敏感，当嵌入中包含"计数/度量"类信息时很有用：例如推荐系统中想推荐与用户已购商品相似的商品，可以用欧氏距离衡量"商品被购买次数"嵌入之间的绝对差。

## 点积相似度（Dot Product Similarity）

两个向量的点积是把对应分量相乘再求和：

```
a · b = a1*b1 + a2*b2 + ... + an*bn
```

点积也可以表示为"两个向量的模长 × 夹角余弦"：

```
a · b = ||a|| * ||b|| * cos(θ)
```

点积是一个标量（单个数）：两向量夹角小于 90° 时为正，大于 90° 时为负，正交（orthogonal）时为 0。

点积同时受向量长度与方向影响。两个向量长度相同、方向不同时，同向则点积更大，反向则更小。想象两个箭头 **a** 和 **b**：指向相同方向时点积，比指向相反方向时更大。

许多大语言模型（LLM）的嵌入用点积训练——按经验法则，索引度量也用点积。例如 Hugging Face 上的 [msmarco-bert-base-dot-v5](https://huggingface.co/sentence-transformers/msmarco-bert-base-dot-v5) 模型明确标注"适用的打分函数"只有点积。

在基于协同过滤与矩阵分解的推荐系统中，每个用户、每个物品（如电影）都有嵌入，模型学到的目标是"用户嵌入与物品嵌入的点积能很好地预测用户对该物品的评分"。此时若两件商品的嵌入方向相同但模长不同，含义是：两者话题接近，但模长大的那个"更好/更流行"。

## 余弦相似度（Cosine Similarity）

余弦相似度衡量两个向量之间的**夹角**：点积除以两个模长的乘积：

```
cos(θ) = (a · b) / (||a|| * ||b||)
```

其中 "•" 是点积，||**a**||、||**b**|| 是向量长度（各分量平方和开根号）。该度量不受向量数值大小影响，只看方向：只要指向相同，数值大或小的向量余弦相似度都一样。取值范围 [-1, 1]：1 表示夹角 0°（尽可能接近），0 表示正交，−1 表示方向相反。

如果嵌入模型是用余弦相似度训练的，你既可以继续用余弦相似度，也可以先归一化（normalize）再用点积——两者数学等价。某些场景归一化 + 点积更快更省，某些场景直接余弦更直观。

余弦相似度的典型用例是语义搜索与文档分类——它比较的是向量的"方向"（即文档的整体内容）。基于用户历史行为做推荐的推荐系统同样适用。

余弦相似度**不适用**的场景：当向量模长本身承载了重要信息、必须参与相似度判断时。例如基于像素强度的图像嵌入比较就不适合用余弦。

## NumPy 手工实现（编者补充）

三个度量用 NumPy 各只需一行，配合上一篇的 FAQ 示例即可验证：

```python
import numpy as np

a = np.array([0.84, 0.42, 0.02])
b = np.array([0.79, 0.45, 0.03])

# 欧氏距离：直线距离，对模长敏感
euclidean = np.linalg.norm(a - b)

# 点积：同时考虑模长与方向
dot = np.dot(a, b)

# 余弦相似度：只看方向
cosine = dot / (np.linalg.norm(a) * np.linalg.norm(b))

print(f"euclidean={euclidean:.4f}, dot={dot:.4f}, cosine={cosine:.4f}")
```

## 小结

再次记住开头的原则：**索引的相似度度量与嵌入模型的训练度量保持一致**。若不知道模型用了什么度量（或向量生成方式本身没有对应度量），就实测多种度量，看哪种在你的数据上效果更好——始终用同一组真值评估来驱动这个决策。
