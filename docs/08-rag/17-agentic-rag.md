**一句话总结**：传统 RAG 管线是线性流程——查询向量化、检索、塞上下文、生成回答。Agentic RAG 用 AI 智能体（Agent）来编排检索、验证与工具调用，从而改进这一切：Agent 能决定搜什么、判断结果质量、必要时再搜、并在生成前综合多个来源。

## 什么是 Agentic RAG？

Agentic RAG（智能体检索增强生成）是一种 AI 架构：由大语言模型（LLM）**自主决定**何时以及如何检索外部知识，并编排查询、验证、综合多源信息的全过程。

与传统 RAG 的固定管线不同，Agentic RAG 系统中的智能体能够：

- 判断是否真的需要检索；
- 选择合适的工具与数据源；
- 把复杂问题拆解为子查询；
- 评估检索内容的质量；
- 迭代式地精炼查询；
- 综合多次检索的信息。

## 什么是 AI 智能体？

AI 智能体（AI Agent）是能自主感知环境、做出决策、并采取行动达成特定目标的系统。LLM 充当智能体的推理引擎，但智能体的能力超越了基础 LLM，体现在：

- **工具使用（Tool Use）**：调用搜索引擎、数据库、API 等外部工具；
- **规划（Planning）**：把复杂任务分解为可管理的步骤；
- **记忆（Memory）**：跨交互维持上下文；
- **自我反思（Self-Reflection）**：评估自身输出并迭代。

## 传统 RAG vs Agentic RAG

**传统 RAG**遵循预定管线：

1. 接收用户查询；
2. 把查询转成向量嵌入；
3. 从向量数据库取回相似文档；
4. 把检索上下文加入提示词；
5. 生成回答。

复杂查询面前，传统 RAG 的局限很明显：

- 单步检索可能漏掉相关信息；
- 不验证检索内容的相关性；
- 无法处理需要多步推理的任务；
- 无论查询复杂度如何，检索策略固定不变；
- 可能召回无关或互相矛盾的信息。

**Agentic RAG** 引入动态决策：

1. 分析查询复杂度；
2. 判断是否需要检索；
3. 规划检索策略；
4. 选择合适的工具与数据源；
5. 评估检索到的信息；
6. 决定是否需要更多检索或工具调用；
7. 综合生成最终回答。

## Agentic RAG 的核心组件

### 1. 智能体框架（Agent Framework）

Agent 是整个 RAG 工作流的中央编排者：处理用户查询、决定检索策略、协调各组件。

### 2. 检索工具（Retrieval Tools）

Agent 可以使用多种检索工具：

- **向量搜索**：语义相似度搜索；
- **关键词搜索**：精确匹配；
- **混合搜索**：组合多种搜索方法；
- **数据库查询**：面向结构化数据。

### 3. 验证与核查（Validation & Verification）

Agent 能通过以下方式验证检索到的信息：

- **相关性打分**：评估文档与查询的相关程度；
- **事实核查**：交叉引用多个来源；
- **完整性检查**：确保必要信息已全部取回。

## Agentic RAG 的收益

1. **动态信息检索**：Agent 根据查询调整检索策略，而非传统 RAG 的"一套管线打天下"；
2. **多步推理**：处理需要多段信息的复杂查询；
3. **来源验证**：回答前交叉验证多个来源；
4. **工具灵活性**：集成向量搜索之外的各种工具；
5. **上下文感知**：跨交互维持对话上下文与用户意图。

## 挑战与权衡

Agentic RAG 优势显著，代价也不小：

- **延迟**：多轮决策与检索拉长响应时间；
- **复杂性**：组件越多，潜在故障点越多；
- **成本**：多次 LLM 推理调用抬高运营成本；
- **调试**：沿决策链追踪问题更困难。

## 实用场景

Agentic RAG 最能发挥价值的场景：

- **复杂查询**：需要跨源拼接信息的多跳（Multi-hop）问题；
- **领域应用**：法律、医疗、技术等需要严格来源验证的领域；
- **多源整合**：把数据库、文档、API 的信息组合起来。

## 示例：Agentic RAG 如何工作

考虑问题："比较 X 公司与其主要竞争对手过去两年的营收增长。"

传统 RAG 可能会：

1. 搜索"revenue growth Company X competitor"相关文档；
2. 取回可能相关的文档；
3. 用找到的东西生成回答。

Agentic RAG 则会：

1. 识别出这是一个需要多个数据点的比较类问题；
2. 分解为子查询：X 公司营收历史 → 识别主要竞争对手 → 竞争对手营收历史；
3. 执行多次有针对性的搜索；
4. 验证检索到的数据覆盖完整的两年区间；
5. 综合出比较结论。

这种多步方法确保在生成回答之前，所有必要信息都已被收集并验证。

## Weaviate 与 Agentic RAG

Weaviate 通过灵活的查询能力支持 Agentic RAG 实现：向量搜索、混合搜索、生成式搜索（单链 RAG）模块，可用于构建复杂的智能体系统。

## 关键要点

- Agentic RAG 用 AI 智能体编排检索与生成；
- Agent 动态决定何时检索、如何检索；
- 这种方式在复杂查询上优于传统 RAG；
- 代价是延迟、成本与系统复杂度上升；
- 对需要跨源推理的应用特别有价值。
