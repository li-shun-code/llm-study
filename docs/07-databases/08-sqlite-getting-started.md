SQLite 与 MySQL、Oracle、PostgreSQL、SQL Server 这类客户端/服务器 SQL 数据库引擎并不能直接比较，因为 SQLite 要解决的是另一个问题。

客户端/服务器引擎致力于实现企业数据的共享仓库，强调可伸缩性、并发、集中化与管控；SQLite 致力于为单个应用和设备提供本地数据存储，强调经济、高效、可靠、独立与简单。

原文有一句著名的定位：**SQLite 不与客户端/服务器数据库竞争，SQLite 的竞争对手是 `fopen()`。**

## SQLite 适用的场景

- **嵌入式设备与物联网**：SQLite 数据库无需管理，适合必须无专人维护运行的设备——手机、机顶盒、电视、游戏机、相机、手表、家电、恒温器、汽车、机床、飞机、远程传感器、无人机、医疗设备、机器人等。客户端/服务器引擎为数据中心的精心运维而生，SQLite 也能在那里工作，但它更能在网络边缘自食其力。
- **应用文件格式**：许多桌面应用（版本控制、财务分析、媒体编目、CAD 等）直接用 SQLite 作为磁盘上的文件格式：File/Open 就是 `sqlite3_open()`，内容修改即自动落盘，File/Save 菜单变得多余。这样做的收益是更高性能、更低成本与复杂度、更好可靠性。
- **网站**：对绝大多数中低流量网站（也就是大多数网站），SQLite 是称职的数据库引擎。官方经验值：日访问量低于 10 万的站点用 SQLite 都没问题——这是保守估计而非硬上限，已有站点用它支撑 10 倍于此的流量。SQLite 官网自己就跑在 SQLite 上（写作时每天约 40-50 万 HTTP 请求，其中 15-20% 是触库的动态页，跑在一台与其他 23 个虚拟机共享物理机的 VM 上，负载均值多数时间低于 0.1）。
- **数据分析**：会 SQL 的人可以用 sqlite3 命令行工具直接分析大数据集：从 CSV 导入原始数据，切片切块生成各种汇总报表；更复杂的分析可用 Tcl/Python（两者都内置 SQLite）或 R 编写脚本。生物信息学研究者常这样用 SQLite。相比企业数据库，它的优势是安装使用更容易，产出的数据库是单个文件，可以拷进 U 盘或邮件发给同事。
- **企业数据缓存**：很多应用用 SQLite 缓存企业 RDBMS 中的相关内容——本地缓存避免网络往返，降低延迟、减轻网络与中央数据库负载，还常能在断网时继续工作。
- **服务端数据库**：把 SQLite 用作应用专属数据库服务器的底层存储：整体仍是客户端/服务器架构，但客户端与服务器之间交互的是应用级请求/响应而非裸 SQL；服务器把请求翻译成多条 SQL，汇总、过滤、分析后返回高层结果。开发者反馈这种场景下 SQLite 往往比客户端/服务器引擎更快——请求由服务器串行化，并发不成问题；配合"分片"（如每个用户一个独立 SQLite 文件）可同时服务成百上千连接。
- **数据传输格式**：SQLite 数据库是单文件、跨平台、格式定义完善的，常被用作系统间传输容器；新增表或列即可扩展格式而不破坏旧接收方，接收方可用 SQL 按需取用，无需一次性解析整个文件。
- **文件归档/数据容器**：SQLite Archive 展示了替代 ZIP/tarball 的可能——体积只略大（某些情况反而更小），且支持增量与原子更新、更丰富的元数据。
- **替代临时磁盘文件**：很多程序用 `fopen()/fread()/fwrite()` 管理自定义格式的数据文件，SQLite 是这类临时文件的优秀替代品——与直觉相反，它读写磁盘可以比文件系统更快。
- **内部或临时数据库**：程序需要以多种方式筛选、排序大量数据时，把数据装进内存 SQLite 库、用 JOIN 和 ORDER BY 提取所需形式，往往比手写算法更容易更快；新增列与索引也不必重写所有查询。
- **演示/测试中顶替企业数据库**：客户端程序静态链接 SQLite 后，就能带着一个 SQLite 数据文件独立做测试或演示。
- **教学**：安装即拷贝一个可执行文件，学生可随意建库、交作业；想研究 RDBMS 实现的高阶学生还能阅读其模块化、注释良好的源码。
- **实验性 SQL 语言扩展**：简单模块化的设计使其成为原型化新语言特性的好平台。

## 何时客户端/服务器数据库更合适

- **客户端/服务器应用**：若大量客户端程序跨网络向同一个数据库发 SQL，请用客户端/服务器引擎。SQLite 可以跑在网络文件系统上，但延迟让性能不佳，且许多网络文件系统的文件锁实现有缺陷——锁不正确时多个客户端可能同时改同一处数据导致损坏，这源于底层文件系统的 bug，SQLite 无力防范。经验法则：**同一数据库将被网络上多台计算机直接（中间无应用服务器）同时访问时，避免用 SQLite。**
- **高流量网站**：写密集或忙到需要多台服务器的网站，应考虑企业级客户端/服务器引擎。
- **超大数据集**：SQLite 单库上限 281 TB（2^48 字节）；即便不考虑引擎，多数文件系统对单文件大小的限制也更低。数据量接近 TB 级时应考虑把内容分散到多个磁盘文件/卷的客户端/服务器引擎。
- **高并发写**：SQLite 支持不限量的并发读者，但任一时刻只允许一个写者。多数情况这不是问题——写者排队，每个事务只持续几十毫秒；但也有应用需要更高写并发，那就得另寻方案。

## 选型清单

1. **数据与应用之间隔着网络？→ 选客户端/服务器。**关系引擎是"降低带宽的数据过滤器"，最好让高带宽的引擎-磁盘链路不出物理机。SQLite 内嵌在应用里，数据与应用分处两台设备时，高带宽链路就得走网络——能用，但次优。（原文注：此处的"应用"指发出 SQL 的代码；若"应用"是应用服务器且数据与其同机，即使用户再多一跳网络，SQLite 仍可能合适。）
2. **大量并发写？→ 选客户端/服务器。**SQLite 每个数据库文件同一时刻只有一个写者；但多数写事务只花几毫秒，多写者排队轮流即可——SQLite 的写并发能力比很多人以为的强。不过有常驻服务器进程协调访问的客户端/服务器系统，写并发上限终究远高于 SQLite。
3. **大数据？→ 选客户端/服务器。**数据会大到塞不进单个磁盘文件时，别用 SQLite。
4. **否则 → 选 SQLite！**设备本地存储、低写并发、不到 1 TB 的内容，SQLite 几乎总是更好的选择：快、可靠、无需配置与维护，"开箱即用"。

> 站内提示：LLM 应用的开发期原型、本地会话历史、评测结果的落盘，SQLite 都是非常合适的默认选择；Python 标准库内置 `sqlite3` 模块，零安装。

## sqlite3 命令行速成

SQLite 项目提供一个名为 `sqlite3`（Windows 上是 `sqlite3.exe`）的命令行程序，可交互地对 SQLite 数据库执行 SQL。先分清两个概念：**SQLite 库**是实现 SQL 数据库引擎的代码；**CLI** 是接收用户输入、转交库求值的应用。人们说"SQLite"或"sqlite3"时，可能指其中任何一个，需结合上下文判断。

**启动**：在命令提示符输入 `sqlite3`，后面可跟数据库文件名。文件不存在时会自动新建；不指定文件则使用临时内存库（程序退出即删除）：

```text
$ sqlite3 ex1.db
SQLite version 3.36.0 2021-06-18 18:36:39
Enter ".help" for usage hints.
sqlite> create table tbl1(one text, two int);
sqlite> insert into tbl1 values('hello!',10),('goodbye',20);
sqlite> select * from tbl1;
┌───────────┬─────┐
│    one    │ two │
├───────────┼─────┤
│ 'hello!'  │ 10  │
│ 'goodbye' │ 20  │
└───────────┴─────┘
sqlite>
```

输入系统文件结束符（通常是 Ctrl-D）退出；Ctrl-C 可中断长时间运行的 SQL。**每条 SQL 命令结尾务必加分号**——sqlite3 以分号判断命令是否结束；漏掉分号会得到续行提示符，等待你继续输入。这正好支持跨多行的命令：

```text
sqlite> CREATE TABLE tbl2 (
   ...>   f1 varchar(30) primary key,
   ...>   f2 text,
   ...>   f3 real
   ...> );
sqlite>
```

**点命令（Dot-commands）**：以点（`.`）开头的行由 sqlite3 程序自己拦截解释，不进 SQL 引擎，通常用于改变输出格式或执行预打包的查询。SQLite 3.52 有 60 多个点命令（输入 `.help` 查看全部，`.help 主题` 看详情）。常用的有：

```text
.help          查看帮助
.open FILE     打开（或新建）数据库文件
.save FILE     把当前库写入文件（.backup 的别名）
.tables        列出表名
.schema        显示建表语句
.indexes       显示索引
.import FILE TABLE   从文件导入数据（支持 CSV）
.mode ?MODE?   设置输出模式（如 csv、column、json）
.output FILE   输出重定向到文件
.dump          把数据库内容导出为 SQL
```

点命令的语法规则：必须顶行首以 `.` 开始（前面不能有空白）；必须整条写在一行内；不能出现在普通 SQL 语句的续行中；没有注释语法。多数点命令可缩写，如 `.q` 是 `.quit` 的常用缩写。CLI 输入是 SQL 语句、点命令与注释的混合序列；SQL 自由换行，以行尾 `;` 结束。

> 站内提示：Windows 用户双击 sqlite3.exe 启动时未指定文件，会连到临时内存库——启动后立即执行 `.open ex1.db`（或用完执行 `.save ex1.db`）即可持久化；路径建议用正斜杠写全路径（`c:/work/ex1.db`）。另外官方还提供浏览器内运行的 CLI 沙箱（sqlite.org/fiddle），可零安装练手。
