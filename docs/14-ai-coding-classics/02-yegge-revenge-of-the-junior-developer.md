## 正文（Steve Yegge 原文全文翻译）

哈喽，哈喽，哈喽！很高兴又见到大家。

这些天我真得开始小心说话了。看着我的眼睛太多了。

所以呢，前几天我放了个屁，听起来像"viiiibecooode"，立刻就有 3 个投资人凑了上来。我不得不跟他们说抱歉那只是个屁，才把他们打发走。

眼下事情实在太多，我又一次写了好几遍这篇文章，每一稿都长得疯狂且难以驾驭，我只好像枪毙老黄狗 Old Yeller 那样把它们全部处理掉。这次我打算趁它还是只幼崽就把发了。（编：该死。至少它从头到尾都是干货。）

关于"vibe coding"含义的简要说明：在这篇文章里，我假设 vibe coding 会长大成熟，人们会把它用于真正的工程，而"关掉大脑"的那个版本会继续存在，只用于原型和好玩的项目。对我来说，vibe coding 就是让 AI 去干活。你选择多紧密地盯着 AI 的工作，完全取决于手头的问题。生产环境，你盯着；原型，你躺平。无论如何，只要不是你亲手写的，它就是 vibe coding。

还有一条：复仇的部分在最最后面，跟电影一样。

好！行政事项交代完毕，我们发车——！

## 第一部分：六波浪潮

Vibe coding 是"基于聊天的编程"一个花哨的名字：你让 LLM 写代码，然后把结果喂回去，再要更多，如此循环。它与传统编程、甚至与带代码补全的编程都非常不同。

聊天式编程在编程助手里已经存在一段时间了，但一直缺一个战斗口号。二月初，联合创办 OpenAI 的名满天下的 Karpathy 博士给"聊天"这张脸起了个漂亮的名字——他叫它"vibe coding"——一夜之间它就成了那条蓝黑白金裙子式的现象。

今天，等我看下表，就在你读这段话的此时此刻，vibe coding 已经进入了一种奇怪的、史无前例的、量子式的三重叠加态：

- 对硅谷之外 80% 的行业来说，vibe coding 依然完全不可见，他们完全不知道我们在聊什么。很多人连"vibe coding"这个词都没听过，更别提"coding agent"了。他们大概从不看新闻？不幸的是，他们都有被 AI 侧撞、不，拦腰 T-bone 的风险。

- 与此同时 vibe coding 正在疯狂爆发式传播，沿着陡峭的指数曲线疯长，登上纽约时报等主流媒体，刷屏社交媒体，有人欢呼，有人痛斥。一批公司正忙着驱逐它，而谷歌却在非官方地拥抱它。大家还在争论"vibe coding"到底是什么意思。但已经有非常多人——而且每天更多——认为它就是眼下的未来。

- 而对一个以更快的指数速度增长的开发者群体来说，聊天式编程总体上已经彻底过气——就算聊天式编程在街上着火，他们也不肯过街去撒泡尿。他们依然在 vibe coding，而且说实话他们的 vibe 比谁都好。但他们对你那种 vibe coding——那种一来一回的长篇聊天——已经毫不在乎了，Good day to you Sir，我说了，Good. Day!

在夸大其词总部（Exaggeration Central），我们发现自己编不出比现实更疯的东西。这一切都是真的，只是展开得太快，让人感觉超现实。

Vibe coding 正在急速攀升，而聊天式编程——你脑子里的 vibe coding，我过去叫它 CHOP——确实也还在上升……目前是。但智能体编程（agentic coding）——本文的主角——很快就将从聊天式编程旁边呼啸而过，仿佛对方静止不动。

到 Q3，今天的聊天式编程对许多人而言将沦为最后才不得不用的可怕备胎，只在你负担不起用智能体超高速干活的时候出场。而在这整个过程中，即便聊天式编程被遮蔽，vibe coding 会长存。

我已经尽力用图 1 表达我个人对这些事情的看法。

图 1 描绘了六个相互重叠的编程浪潮：传统（2022）、补全式（2023）、聊天式（2024）、编码智能体（2025 上半年）、智能体集群（2025 下半年）和智能体舰队（2026）。

图中，传统和补全式——两种手工模态——正在衰落，其余都在指数上升。从聊天开始，每一波新浪潮的上升速度都远快于前几波。最后，图中把 vibe coding 也画成指数上升，但是一条与其他曲线并行的虚线，因为我们很快会看到：vibe coding 不是一个模态。

作为后文的预告："agent clusters"（智能体集群）是我用来指代"开发者能够并行运行并卓有成效地管理许多编码智能体，数量甚至可能超过本地机器能装下的规模"的占位术语。而"agent fleets"（智能体舰队）是当我们给叶子节点配上 AI 督导者之后发生的事情，如图 2"FY26 组织架构图"所示。

这张图显示，组织里所有一线（叶子节点）开发者都像二级直线经理一样运转，管理着若干 AI"经理智能体"，而这些经理智能体又各自督导着一组编码智能体。比如，在一名 IC 开发者的指导下，一个受管智能体组可能在清理 bug 积压，另一组在开发新业务功能，第三组在做一场旷日持久的架构迁移。好一片名副其实的智能体农场！

这当然只是对未来展开方式的一个粗糙近似，但我觉得够接近了。我们都预测过"第四波"编码智能体会来，而且它们来得比大多数人预期的更快。现在人工跳上第五波也已经是可能的，虽然费劲。我自己就在并行跑两个智能体。当你这样做时，会很明显地发现：许多工作可以借助智能体来辅助智能体完成。

智能体怎么辅助智能体？今天，你得自己注意到某个智能体工人卡住了、干完了、或者跑偏了，然后适度推它一把。督导智能体很快就能替我们做掉大部分这种事。结果就是：第六波。开发者将有能力让大型编码智能体舰队的工作队列保持满载，一路碾过企业遗留代码的崇山峻岭。那将是一片辉煌。

而这些魔法般的智能体舰队最迟 2026 年初就会到来。因为造它们其实没那么难——我们本来就很擅长把工作并行化。

以上是闪电式开场。后面还有大把内容。如果这一切对你来说是个巨大的意外，那么未来几个月你会走得比较颠簸。

## 第二部分：你在哪里？

如果你仍然把"AI 代码自动补全建议"当作程序员使用 AI 的主要方式，和/或你仍在度量补全接受率（CAR），那么你就是坐在图 1 里那条隐约呈恐龙形状的"传统编程"曲线上。这条曲线大约在 2027 年超级滑向过时。

我有个坏消息：代码补全一年前非常流行，那段时间现在感觉像遥远的先导篇。但它们如今已经是 AI 界的"行尸走肉"（dead man walking）。

如果你稍微前卫一点，你可能认为今年展开的方式是聊天式编程——也就是 IDE 内的编程助手聊天界面，比如 Copilot、Cursor、Sourcegraph 和 Windsurf。如果你在这一组，那你其实混得不算差。中游水平，拍拍背。你至少采用了一个有用的模态——与代码补全相比极其有用——而聊天的人气也还在涨。

但突然之间我们有了这最新一波，新的编码智能体，比如 Aider.chat 和 Claude Code——很快，类似但更漂亮的智能体也会出现在你喜欢的所有 IDE 里，眨眼，暗示，咳嗽。

一旦你试过编码智能体，并摸索出如何高效使用它们，你就再也不想回去了。它们会碾压聊天式编程。而最棒的是：用智能体时你依然在 vibe coding。这正是它不是模态的原因：你可以用任何非手工的 AI 模态来 vibe code：聊天、智能体、集群。只要 AI 在干活，你就在 vibing！跟智能体唯一的区别是，你不用那么频繁地和它们碰头。

既然智能体已经出现，我们开始能看出规律。从聊天开始，每一代模态浪潮的生产力保守估计是上一波的 5 倍。聊天可以达到手工编程的 5 倍生产力，智能体可以达到聊天的 5 倍，以此类推。注意，如果不被打扰并给足成熟时间，每一波大概能长到上一代的 10 倍。但它们总是被新的、更快的模态拍平。

这就是我今天看到的局面。我们身处 AI 大洋中的一场大竞赛，被越来越猛烈的浪头拍打。活下来的人会骑上那些浪。每家公司都处在图 1 一条或多条采用曲线上的某个位置。你在哪里？

以上就是我对未来的可爱又迪士尼化的心智模型。我断言，即将到来的集群与舰队浪潮不仅不可避免，而且近在眼前。Vibe coding 仍将是这片图景中持久而恒定的特征——但不是大多数人以为的那种方式。Vibe coding 的含义，说穿了就是：从此再也不用手写代码。

如果你跟上了我的思路，那我们来看看财务影响。首先让我快速给你补补课：编码智能体是怎么工作的——并不复杂，你就是开始烧钱，烟雾会让它们变聪明。如果你没跟上，我劝你去玩玩这些新的编码智能体。认真的。或者去看一个会用的人玩。

无论你是被说服了还是将信将疑，至少来看看这些新编码智能体到底是怎么工作的。因为这里没有任何魔法。

## 第三部分：新骆驼主人手册

我们来看看为什么这个才几周大的新事物，会迅速把你的公司逼进真正的困境。用英式话说：一个不折不扣的 pickle（一团乱麻），一壶好鱼（a fine kettle of fish，一桩糟心事）。

关于软件编码智能体的说法我们以前听过。但这次不一样。这些"真"编码智能体仍然非常非常新，满打满算几周大，而且它们只在 1970 年代 Unix 风格的纯文本终端里运行。得到一个这种东西，就像你走了一辈子路，然后有人送你一匹免费的骆驼。事实上他们说，想要多少该死的骆驼就拿多少。拥有一匹很美妙。一匹。比起走到哪儿都靠双腿，它们很棒，但它们会朝你吐口水、咬你，而且需要大量绿叶食物，主要是五十和一百面额的。

你们中的很多人——我知道这是事实——一直对聊天式编程超级怀疑。我甚至听说有些开发者已经向他们的经理清楚且毫不含糊地表示：他们想继续亲手写代码。他们说这就是他们来这儿的目的。写。代.码。他们说得很慢，好像觉得你耳背，慢一点能帮你听清。他们声称永远不会把自己的编码工作委托给 AI。嗨，说你呢！我看到你了。

所有你们这些怀疑论者，应该把手头正在做的事或者手里的东西直接扔地上，然后发疯似的奔向离你最近的那匹骆驼，跳上去。下载并试用一个编码智能体，最好是 2025 年 3 月 1 日之后发布的那个。因为它们会把你对"用 AI 编程"的所知或自以为所知彻底倒转过来。就在三周前，我自己都几乎不敢相信亲眼所见。

编码智能体原理上很简单。它们的工作方式跟典型的 vibe coding 聊天会话一样：LLM 完成大部分分析和重活，而你基本只负责戴耳机。但用智能体时，你不必做那些丑陋的双向复制粘贴和配套提示词——那是慢吞吞的"人类环节"。取而代之，智能体接管并替你处理这些，只在它完成、卡住、或者你钱包见底时才回来找你聊。

而且它们经常在完全无人协助的情况下推进得相当远。它们只会对着任务埋头苦磨直到做对，按需向问题上倾倒 token 来探索解空间。人类从 90-99% 的工作中被移出了瓶颈位，除此之外，它就像一个更快的聊天式 vibe coding 版本。

除了成本，与聊天唯一的实际区别是：智能体一次能执行大得多的子任务，可能涵盖许多个单独步骤。在这段时间里，监督的开发者被解放出来，去干重要的工作，比如吃完那袋奇多，再刷刷 HN。

说得具体点，你可能对一个编码智能体说："这是 JIRA 工单号；请去修掉它。"你只需要说这么多。智能体会先努力获取 JIRA 工单的访问权：它可能会找 JIRA 命令行工具，甚至可能问你可不可以下载它。它甚至可能给自己写个一次性程序，用编程方式拉取工单字段。我们经常看到它们写一次性程序。

一旦智能体能读到工单，它就使用你机器上的工具，像你一样检查你的代码，把 bug 揪出来。它会对每个工具请求你的许可——这是今天整个流程里最大的减速带之一。找到 bug 后，它会提出修复方案，写测试验证修复，运行那些测试，并做出让测试通过所需的其他改动——绝大部分情况下全程循环、不需要你。

这些新的编码智能体能解决巨大的 issue，也能制造更大的烂摊子，整体行为像一个快得不正常的真人开发者，总是有点盲飞，总是有点赶工期。

这听起来像科幻，但你现在就能用上它们。

要理解一点：这些新智能体目前每次仍只能处理"偏小到中等偏大"级别的任务。任务图分解——我们在远古聊天时代（去年 12 月）都学会的技能——在你切换到用智能体 vibe coding 时依然同样重要。甚至更重要，因为用智能体时太容易用力过猛、太好高骛远。它们有效得可怕，你很容易贪心，然后把会下金蛋的鹅捂死。

对你的鹅好一点。别塞太满。你需要拆解任务，并细心放牧你的编码智能体。如果你给其中一个太大的任务，比如"请修好我全部的 JIRA 工单"，它会猛扑上去，然后几乎寸步难行。今天，它们需要仔细的监督和深思熟虑的问题挑选。简言之：它们是难伺候的牲口。

但这会变。还没等你抽完一鞭子，说到牲口——智能体会悄悄爬进你的 IDE，不再是骆驼，而是备好鞍的马：大体上是一次人机工学升级，当然，是受欢迎的那种。拥有一个不能以高精度把恶臭液体吐到三十六米外物体上的工具，还是挺好的。

从现在起，工具的每一次迭代都会让编码智能体更易用、更可并行、更强大。而且今年我们就会更频繁地看到真正戏剧性的飞跃。

战车是下一站。等着瞧吧。

## 第四部分：说好的没有数学呢

这一节是给 CIO 和财务同学的。你好。谢谢你读到这里。

在几周前刚收尾的 FY26 规划里，你给开发者的 LLM 花费留了多少 opex 预算？一点点？很多？有家公司告诉我，他们在考虑每开发者每天 25 美元的慷慨预算。这听起来很大胆，像很多钱。几乎算鲁莽的金额。

结果呢，他们其实走在正道上。编码智能体是 très cher、muy caro——我们说的是非常、非常贵。它们烧大量 LLM token，按当前价格约合每小时 10-12 美元。你的编程助手每个席位许可现在多少钱？一个月 30 刀？大概这个数？也许更少？

为了方便计算，有个经验法则：每个编码智能体实例摊销到本财年，其价值约等于多雇了一名初级软件开发者——前提是有人（人类或 AI）让它每天保持 8-10 小时的忙碌。

这个经验法则相当震撼。我相信你会同意：一小时十美元，雇一个只需要好保姆的专业软件工程师，简直是白捡。

所以更值得考虑的预算是：每开发者每天 80-100 美元的 LLM 花费。每天 30 刀只够骑三个小时骆驼，然后你的开发者们午饭后就得继续步行上班。但如果你付足一张富兰克林，你的每个开发者都能轻松翻倍产出，因为他们可以当两个智能体的保姆，同时还有空干点别的。不用动脑子都知道划算。

然而。

即将到来的浪潮——我称之为"智能体集群"，就是上一节暗示的战车——应该在 Q3 登陆。这一波将让你的每个开发者同时并行运行许多智能体，每个智能体干不同的任务：修 bug、细化 issue、做新功能、清理积压、部署、写文档，字面意义上的任何开发者会做的事。

你的每个开发者都会突然变成许多个开发者。至少擅长这件事的那些会。（伏笔：我闻到了复仇的味道。）

智能体集群还有一个副作用：最终把软件开发搬进云端。人们预测云端 IDE 已经几十年了！对吧？你们中一半人可能都尝试过造一个。这主意看上去如此显然。

但本地跑 IDE 一直更方便，所以云端开发从未起飞。2025 下半年的智能体集群浪潮将改变这一点。你的开发机没有足够的算力同时跑几十个智能体，更别提几百个。开发者的主要工作几乎会一夜之间迁移到云上。

所以你可能需要更多云预算。

同时跑 N 个智能体，会把你的开发者每天 10 美元/小时的无害开销乘以 N，这还没算云成本，只是 token 燃烧。如果你的开发者平均每人同时跑，比方说，五个智能体——这是个非常保守的数字，因为智能体基本独立工作，开发者有空干别的——那么这些开发者每人现在的开销是 50 美元/小时，约合每年 10 万美元。

这已经不算白捡了，更像明抢。我们讨论的是：到 2025 年 Q4（算上爬坡期），每个开发者以约 5 倍的乘数逐步提升生产力，第一年额外摊销成本仅约 5 万美元/年。这种买卖谁不做？

不幸的是，你几乎可以肯定没有把每开发者 5 万美元/年的 LLM 花费算进 2026 运营预算。这一局面将迅速把公司分成"有预算的"和"没预算的"，而有的会，有的更狠。没有的连一半都难有。跟上我的思路了吗？

说得更直白一点：软件开发现在是一趟付费上车的子弹头列车。买不起票，你就有被红移出大部队的风险。

## 第五部分：智能体舰队来了

从这里开始有点让人不舒服了。如果你已经在冒汗，或者感到任何心悸，也许歇一会儿，喝口汽水，把简历掸掸灰，都行。慢慢来。不着急，我们等你。

好，从这里起，大家保证保持冷静，童子军起誓。开始吧。

集群之后的浪潮，或者叫智能体"舰队"，因为没找到更好的词，将让你的开发者一次运行 100+ 个智能体……借助更多的智能体。督导智能体将能运行编码智能体的小组或"豆荚"（pods），代为调停，只在智能体真的卡死时才把人类拉进来。

从今往后，软件开发者的新工作，将是管理编码智能体及其 AI 督导的仪表盘，如图 2"FY26 组织架构图"所绘。有人也许轻蔑地管这叫"当保姆"，并指责 AI 是些哼哼唧唧的婴儿机器人，需要大人把食物切成小块、换尿布、收拾烂摊子、防止它们爬出游戏围栏。但我们更愿意称之为软件开发。这就是我们的命运。

对 CIO 们来说，舰队将让你的开发者每天花掉数千美元。即便推理成本暴跌，杰文斯悖论（Jevons Paradox）也会让用量上涨抵消掉降下来的成本。如果你不信，去看看你的 bug 积压吧；它基本是无限的。

一天几千刀？！但这钱花得值到家了！你的工程组织将开始能够跑出你一直想要的速度，破天荒头一遭。敢信吗？就像重新变回一家创业公司。你将能"给客户带来惊喜和愉悦"——借用杰夫·贝索斯爱说的话——而且是在你做梦都不敢想的精英水准上。

但你得从某处找出一大笔新预算。也许你走运，你公司财大气粗。举个例子，就在发稿前我刚听说，某个你们都认识的大品牌今年拨了一笔非常大的 LLM 实验小金库。我猜有多少家公司这么干了，并因此在无意中躲过了今年预算规划的黑天鹅？

如果你把沙发缝都翻遍了也凑不出每开发者年底前额外的 5 万美元，也许你可以想办法融资。这件事眼下可能更有利于创业公司而不是大公司。我觉得智能体这件事已经把很多竞争场地给拉平了。

这个故事吓人的部分是：如果你找不到也融不到钱，又想保持竞争力，那你就得做痛苦的削减来腾出 opex 预算。而你再算算账，只有一个部门的削减是说得通的。

剩下的部分，恐怕就留给读者自行练习了。我不知道会发生什么。我只是个路人。也许这一切都被夸大了，你只需要在我的预测上加六个月它们才会成真。我和 Claude 为这事争论了一会儿，Claude 投降了，说如果把我所有估计放宽六个月，它是成立的。所以坏消息也许没那么坏！

现在来点好消息！你确实先问了坏消息，对吧？反正不管怎样，它过去了。接下来轻轻松松，我们也快结束了。剩下的只有甜甜的、甜甜的复仇。

## 第六部分：初级开发者的复仇

事实证明，前路并不全是毁灭与阴郁。差得远呢！软件行业会有大量工作。只是不再是那种像野蛮人一样手写代码的工作。

自从我发表《初级开发者之死》以来，过去一年里我观察到的一个稳定模式是：初级开发者实际上比资深开发者更热衷于采用 AI。这不绝对；有几个人告诉我们，他们的初级员工害怕使用 AI，因为他们多少不太理性地觉得 AI 会抢走自己的饭碗。（参见：行为遗憾理论。谢谢你的指点，Daniel Rock 博士！）

但大体上，初级开发者——包括 (a) 刚出道的开发者、(b) 还在读书的开发者、(c) 还在琢磨要不要上学的开发者——都上手极快。他们抓起那本《O'Reilly AI Engineering》——现在所有开发者都得把它从头到尾啃完——把它当岗前培训。他们全都在用聊天式编程，全都用编程助手，而且我知道你们当中有一批初级开发者已经在用编码智能体了。

初级开发者们正在 vibing。他们懂了。世界在变，你必须适应。于是他们就适应了！

而资深开发者嘛……说好听点，正在挣扎。我不缺好朋友，跟我一样的老家伙，基本从没碰过 LLM，甚至没见过活体。还有不少人只是浅尝过编程助手。我甚至从多位行业领袖那里听说，有资深开发者群体公开站队反对 AI。

举个例子：一个知名品牌的技术总监刚告诉我，他们有个开发者给上级发了一份 PDF，用彩色幻灯片和图表论证为什么大家应该放弃 AI、回归常规编程。现在你明白我说"我们拥有科技史上理解分布最悬殊的一代"是什么意思了吧？还有人觉得这事儿跟加密货币差不多。我勒个去！

听着，有些资深开发者挣扎，毫无疑问，只是因为他们太忙。我理解。但我认为对其中大多数人，有更深层的东西在起作用。我以前写编程语言博客的时候发现，仅仅说一句"我喜欢某门编程语言"——任何语言都行——就会让我意外地陷入大麻烦。人们会在评论区吼叫，电子唾沫横飞。我搞不懂状况。就因为我说我喜欢一门语言？

好几年后我才明白：是因为他们觉得，如果人们听了我的话，所有人都会切换到那门语言，然后资深开发者们也不得不学它。他们把"不得不学新东西"——我是说真正的新东西，有点像从头再来——等同于丢工作、丢医保、破产、死在医院外的台阶上。这只是人性在巨大不确定变化面前的正常运作。

我相信，可悲的是，那些拒绝 AI 的人在现状里押了太多注，他们痛苦而错误地把现状等同于工作安全感。他们都对自己说：AI 还没证明它在 X、Y 或 Z 上比我强，所以它还没准备好。

但在我这个位置看过去：没准备好的是他们。我把这一切摊开讲得这么细，朋友们，就是为了你们能自救。

且不论这些勒德分子为什么不采用，他们已经输了。初级开发者占据了高地，战斗已经结束。不仅初级开发者平均采用 AI 更快，而且初级开发者——惊喜！——更便宜。如果公司要削减开支，好付 token 费用让开发者赢下这场战争，你觉得他们会留下哪些开发者？

AI 的死硬分子们还没看到这些在逼近，所以初级开发者们得放下光剑，从山丘顶上把这个消息喊下来：

**证明自己比你要强，不是 AI 的职责。用好 AI 让自己变强，才是你的职责。**

否则，你就会得到……else 分支。你懂的。else 分支。岩浆。你掉进去了。为什么这种事还要我明说？

好！我们来到电影的结尾了。你撑到了。击个掌，初级开发者们！✋我去年没料到这一幕，但你们竟然成了把失败者投票下岛的人，我对此印象非常深。也向那些已经想明白、早已上路开进的资深开发者们击个掌。你们的人数比人们以为的要少，至少在湾区泡泡之外。

至于剩下的各位……倾身向前，拥抱它。像个 Junior。认真的。不管你是谁，甚至不管你是一个人还是一家公司。向前倾。是时候了。AI 已经在这里。

在 Sourcegraph，我们每天都在死磕这个问题空间。我们正在朝这样一个世界努力：这一切尽管贵得吓人，却正在变得惊人地、并且很快将无可争辩地有价值——对每一个选择使用它的人而言。编码智能体大军正在渡过卢比孔河，而把它们接入企业知识产权资产和代码库，将是下一场大戏。那就是我们的聚焦点。

更宏观地说，我们所有人都认为会有工作。很多工作。我们认为当前的招聘冻结只是公司在释放"还不知道该怎么办"的信号。但就在本财年，各种体量的公司都可以比以往任何时候更雄心勃勃，我说这话没有一丝夸张。如果历史可以参考——从蒸汽到电力再到计算——我们很快将看到多得多的人在创造软件。由此而来的生产力浪潮可能把多国 GDP 推高令人咋舌的幅度，100% 或更多。

但要参与进来，你必须学习下一波浪。作为一名开发者，见鬼，哪怕你是 PM 或任何泛技术岗位——你需要补上编码智能体这一课，并且保持不掉队。不要再磨蹭和浅尝辄止了。现在就搞清楚怎么使用一个自动化编码智能体，在你知道如何驾驭它之前别放弃。推它，直到它为你所用。

也别太得意忘形地推太狠。编码智能体就像你用惯了动力铲之后给你的一台巨型隧道掘进机。它很强，是的，强得要命。但它很贵，它仍然会严重卡死，你需要时刻小心引导它。而且它没那么快——它不会一天挖通英吉利海峡。所以别一上来就设定不切实际的预期。专注于这件事与两年前 ChatGPT 横空出世时有多不同，然后再惊叹它与两个月前——我们最好的工具还只是聊天——有多不同。

玩得开心。它叫 vibe coding 是有原因的。事实证明，不写代码挺容易的。

别掉进诱人的"工作延期"陷阱。说"六个月后工具会快得多，所以我把活儿推后六个月"，就像说"我要等车流变少了再出发"。你的车程确实会更短。但你会最后一个到。

智能体正在到来。浩浩荡荡的舰队。不只是编码智能体。智能体正在四面八方涌现，贯穿整条业务与生产技术流程。今天上午我和一个大客户聊过，他们已经造了几十上百台"AI 任务机器"——执行其庞大工作流中特定环节的定制智能体。未来已来。智能体已至。

如果你需要一个行动号召，那么我给人类和公司的建议是同一条：切换到聊天。丢掉补全。停止手写代码。学习验证与确认（validation and verification）在新世界如何运作。熟悉这个领域，跟踪最先进水平。别再抱怨了，把这一切变成一道工程练习题。保持在线。你能做到。

最重要的是，密切注意新的编码智能体。它们今天对大多数开发者可能还几乎不可用，但不会太久。一点也不久。它们是贵得惊人的生产力机器——而与人类相比，又是跳楼价。艰难的选择就在前方。

到今年年底，"软件工程师"的新工作内容，将几乎不包含直接编码，而包含大量智能体保姆工作。你越早上船，日子越好过。

如果你读到这里还是不知道该干什么，去找个初级开发者帮忙吧。

差不多就这些。我们即将迎来《Cheating is all you need》两周年。从那以后变化之大，简直疯狂。如果我能把这篇博客传送回过去，两年前的我自己绝对不会相信。

感谢我的老板 Quinn Slack 在一周前用这些点子把我震了个天旋地转。希望本文对你多少有点用。我要去投资人身上放屁了。再见！

## 2026 年回看

> **以下为本站编者注，非原文内容。** 原文写于 2025 年 3 月，语气是讽刺加预言。下面按"已成共识 / 已被工具内置 / 该修正的地方 / 今天怎么用"四档给判断（均为编者观点）。

**已成共识**

- **"智能体舰队 + 督导智能体 + 管理仪表盘"**成了现实方向：多智能体编排、subagent 嵌套、后台会话与 CI 里的无人值守智能体（《多智能体协作编码》《Headless 与 CI 中的 AI 编码》），正是他那幅"FY26 组织架构图"的严肃版本。
- **"初级开发者比资深者更热心采用 AI"** 被后续数据普遍支持，"管理智能体"确实成了岗位职责——今天的说法是 harness 工程与评审带宽管理。
- **"生产盯紧、原型躺平"的分级监督**已落到产品里：权限模式、沙箱边界、worktree 隔离，就是把"盯多紧"参数化（《Claude Code 权限系统与安全机制》）。
- **杰文斯悖论的判断成立**：单位成本下降，用量与总花费反升。

**已被工具内置（不必再自建）**

- 他设想的编排层已是开箱能力：动态工作流、subagent 与并行 worktree、云端评审智能体、生命周期 hooks；重复流程沉淀成 Skills。
- "每位开发者年底多 5 万美元"这种预算，今天由订阅档位与用量面板管理（《成本管理：Token 消耗、订阅选择与用量优化》《团队落地》）；"被红移出去"的冲击叙事更像背景情绪，不再是决策依据。

**该修正的地方**

- **他算的是产能账，没算评审与 CI 账。** 公开数据把瓶颈写得很清楚：Anthropic 自己六个月里 CI 任务量涨 25 倍；对 33,707 个智能体 PR 的分析显示，需要迭代精化的那批常"消失"，给维护者留下注意力税——舰队能开出去，前提是评审与验证跟得上。
- **他没算安全账。** 无人值守的多智能体意味着更大攻击面（提示注入、外泄通道、凭据滥用）——用《AI 代码的安全与质量陷阱：六大陷阱与检测清单》的 lethal trifecta 与 OWASP 智能体清单覆盖这一格。
- **那幅组织架构图是讽刺漫画**，别当规划图：任何"100 个智能体"的设想，先落在"2—3 个并行分支 + 一套不可绕过的闸门"上。

**今天该怎么用**

1. 把"六波浪潮"当**阅读地图**而非路线图；把"给 CIO 的算账课"换成三个你能自测的数：**评审前置时间、缺陷逃逸率、每交付功能的 token 成本**——它们不恶化，扩张才有意义。
2. 读第六部分时补一条他当年没写的判断：初级开发者拿到的是**杠杆**，支点仍是测试、边界与审查（《TDD with AI：Kent Beck 的增强编程实践》）。
