微调与部署的最后一课是安全。你的模型一旦对外服务，就要面对提示注入、数据泄露、越权工具调用等真实攻击面。本文用两个权威来源回答：风险全景是什么（OWASP），工程上怎么加护栏（NeMo Guardrails）。

## OWASP LLM 应用十大风险（2025 版）

OWASP GenAI Security Project 发布的《2025 Top 10 Risk & Mitigations for LLMs and Gen AI Apps》覆盖生成式 AI 与大模型应用在开发、部署、管理全生命周期中的十大风险。

**表：OWASP LLM Top 10（2025）**

| 编号 | 风险 | 一句话定义 |
| --- | --- | --- |
| LLM01 | 提示注入（Prompt Injection） | 用户提示改变 LLM 行为或输出，产生非预期结果 |
| LLM02 | 敏感信息泄露（Sensitive Information Disclosure） | LLM 或应用上下文中的隐私/机密数据经输出外泄 |
| LLM03 | 供应链（Supply Chain） | 训练数据、模型、部署平台的供应链完整性风险 |
| LLM04 | 数据与模型投毒（Data and Model Poisoning） | 训练/微调/嵌入数据被操纵，引入漏洞、后门或偏见 |
| LLM05 | 不当输出处理（Improper Output Handling） | LLM 输出在传入下游系统前缺乏校验与净化 |
| LLM06 | 过度代理（Excessive Agency） | LLM 故障时能触发破坏性动作，权限过大 |
| LLM07 | 系统提示词泄露（System Prompt Leakage） | 系统提示词被发现并被用于辅助后续攻击 |
| LLM08 | 向量与嵌入弱点（Vector and Embedding Weaknesses） | RAG 系统中向量的生成/存储/检索可被利用 |
| LLM09 | 错误信息（Misinformation） | 模型产出看似可信的虚假/误导内容 |
| LLM10 | 无限制消耗（Unbounded Consumption） | 不受控的推理消耗导致 DoS、经济损失与模型窃取 |

### LLM01：提示注入（重点条目）

当用户提示改变 LLM 的行为或输出、使其以非预期方式运作时，即出现提示注入漏洞。这类输入即使人类不可感知也能影响模型——只要内容被模型解析，注入就不需要人眼可见/可读。

提示注入漏洞存在于模型处理提示的方式中：输入可能迫使模型错误地把提示数据传给模型的其他部分，进而违反准则、生成有害内容、获得未授权访问或影响关键决策。虽然 RAG 与微调旨在让输出更相关、更准确，但研究表明**它们并不能完全消除提示注入风险**。

提示注入与越狱（Jailbreaking）经常混用：提示注入是通过特定输入操纵模型行为（可包括绕过安全措施）；越狱是提示注入的一种——攻击者让模型完全无视安全协议。开发者可以在系统提示词与输入处理中构建防护，但有效防止越狱需要持续更新模型的训练与安全机制。

**两类注入**：

- **直接注入**：用户输入直接改变模型行为（恶意蓄意或无意触发）。
- **间接注入**：LLM 接受来自外部来源（网页、文件等）的输入，其中被模型解析的内容改变模型行为。

成功的注入攻击可导致：泄露敏感信息（含系统基础设施与系统提示词）、内容操纵产生错误/偏见输出、越权调用 LLM 可用功能、在连接的系统上执行任意命令、操纵关键决策。多模态模型还引入独特风险——攻击者可在伴随良性文本的图片中隐藏指令。

**缓解策略（OWASP 原文要点）**：

1. **约束模型行为**：在系统提示词中明确角色、能力与限制；强制严格遵循上下文；指示模型忽略修改核心指令的企图。
2. **定义并校验输出格式**：规定清晰输出格式、要求推理过程与引用来源、用确定性代码校验格式遵从。
3. **实施输入输出过滤**：定义敏感类别并构造识别规则；应用语义过滤与字符串检查；用 RAG 三元组（上下文相关性、有据性、问答相关性）评估响应。
4. **权限控制与最小特权**：为扩展功能给应用单独的 API token，在代码中处理这些功能而非交给模型；把模型访问权限压到最低。
5. **高风险动作需人工审批**：对特权操作实现 human-in-the-loop 控制。
6. **隔离并标识外部内容**：分隔并明确标注不可信内容，限制其对用户提示的影响。

### 其余九项风险要点

- **LLM02 敏感信息泄露**：PII、财务、健康记录、商业机密、安全凭据等都可能经模型输出外泄。缓解：对进入训练的数据做充分脱敏；提供清晰使用条款并允许用户选择退出训练；在系统提示词中限制可返回的数据类型（但此类限制不保证被遵守，可能被注入绕过）。
- **LLM03 供应链**：第三方预训练模型与数据的完整性风险。开源权重平台上的 LoRA/PEFT 微调玩法引入了新的供应链风险——下载的适配器/数据集同样可能被篡改。
- **LLM04 数据与模型投毒**：针对预训练、微调、嵌入各阶段的完整性攻击；外部数据源风险尤其高。经共享仓库分发的模型还可能通过恶意 pickle 等技术在加载时执行代码；后门可潜伏至特定触发条件才生效，极难测试发现。
- **LLM05 不当输出处理**：LLM 输出可被提示输入操纵，直接传给下游组件相当于给用户开了间接入口；被利用可导致 XSS/CSRF、SSRF、提权或远程代码执行。核心是按下游上下文（HTML/JS/SQL）做输出编码与校验。
- **LLM06 过度代理**：LLM 系统常被授予调用工具的代理能力，甚至把"选哪个工具"交给 Agent 动态决定。无论 LLM 为何 malfunction（幻觉、被注入、同伴 Agent 被污染），只要它能触发破坏性动作，就是过度代理漏洞。解法是限权 + 人工审批。
- **LLM07 系统提示词泄露**：系统提示词**不应视为秘密，也不应作为安全控制**——凭据、连接串绝不能写进系统提示词；真正的风险是应用把会话管理与鉴权"委托"给了 LLM。
- **LLM08 向量与嵌入弱点**：RAG 场景下向量的生成、存储、检索弱点可被用来注入有害内容、操纵输出、访问敏感信息（跨租户检索、知识库投毒等）。
- **LLM09 错误信息**：幻觉是主要成因（用统计模式填补训练数据空缺），训练数据偏见与信息不全也有贡献；用户的**过度依赖（Overreliance）**会放大影响——不核验就把错误内容并入关键决策。
- **LLM10 无限制消耗**：无限制的推理调用可导致 DoS、经济损失、模型窃取（通过大量查询克隆模型行为）与服务降级。需要限流、配额、异常消耗监测。

## 工程落地：NeMo Guardrails

OWASP 告诉你"防什么"，NVIDIA 开源的 NeMo Guardrails 给出"怎么防"——在应用代码与 LLM 之间加一层**可编程护栏（Programmable Guardrails）**。

### 核心能力

- **构建可信、安全、可靠的 LLM 应用**：定义护栏引导与守护对话；指定应用在特定话题上的行为，阻止其进入不希望的话题。
- **安全连接模型、链与服务**：把 LLM 与其他服务（工具）安全地连接。
- **可控对话**：引导 LLM 遵循预定义对话路径，按对话设计最佳实践设计交互，强制执行标准操作流程（如鉴权、客服）。

NeMo Guardrails 还内置了对常见 LLM 漏洞（越狱、提示注入）的防护机制，并提供了漏洞扫描工具量化防护效果。

### 五种护栏类型

**表：NeMo Guardrails 的五类护栏**

| 类型 | 作用位置 | 可做动作 |
| --- | --- | --- |
| 输入护栏（Input rails） | 用户输入上 | 拒绝输入、中止处理；或改写输入（如掩码敏感数据） |
| 对话护栏（Dialog rails） | 提示 LLM 的方式上 | 基于规范形式消息决定执行动作、调用 LLM 生成回复，或改用预定义回复 |
| 检索护栏（Retrieval rails） | RAG 检索到的片段上 | 拒绝片段（阻止其进入提示）、改写/掩码片段 |
| 执行护栏（Execution rails） | 自定义动作（工具）的输入输出上 | 校验/拦截工具调用 |
| 输出护栏（Output rails） | LLM 生成的输出上 | 拒绝输出（不返回给用户）、改写（如移除敏感数据） |

### 使用方式

Python API 的调用方式与直接调用 LLM 几乎一致，只需两步：加载护栏配置创建 `LLMRails` 实例；用 `generate`/`generate_async` 调用：

```python
from nemoguardrails import LLMRails, RailsConfig

# 从指定路径加载护栏配置
config = RailsConfig.from_path("PATH/TO/CONFIG")
rails = LLMRails(config)

completion = rails.generate(
    messages=[{"role": "user", "content": "Hello world!"}]
)
```

输入输出格式与 OpenAI Chat Completions API 兼容；库是 async-first 的（核心机制基于 Python async 模型，同步/异步方法成对提供）。支持多后端 LLM。

**适用场景**：

1. 文档问答（RAG）：强制事实核查与输出审查。
2. 领域专属助手：确保话题不跑偏、对话流程按设计走。
3. 自定义 LLM 端点：为面向客户的交互加护栏。
4. LangChain 链（可选）：在链外包一层护栏。

护栏配置定义要用的 LLM 与一条或多条护栏（config.yml + Colang 对话流定义），没有任何护栏的配置等价于把请求直通 LLM。除 Python API 外还提供 Guardrails Server（独立服务化）与 Docker 部署、CLI 工具、评测支持与遥测。

## 合规提示（编者补充，非法律意见）

在中国大陆提供生成式 AI 服务需关注《生成式人工智能服务管理暂行办法》（2023-08 生效）及配套的生成式 AI 服务安全基本要求等标准：核心义务包括训练数据合法性、内容标识（生成内容显式/隐式水印）、用户实名、未成年人保护、投诉举报机制与安全评估备案。面向海外服务则涉及欧盟《人工智能法案》（AI Act）按风险分级的义务。开源模型 ≠ 免合规：**自部署模型同样受上述义务约束**。上线前建议完成：内容标识接入、敏感话题拦截清单、日志留存方案与安全评估流程。

## 部署前安全清单（编者补充）

- [ ] 系统提示词中不含凭据/连接串等秘密（LLM07）
- [ ] 所有工具调用走最小特权 + 人工审批高风险动作（LLM01/06）
- [ ] LLM 输出按下游上下文做编码/校验后再进数据库/HTML/Shell（LLM05）
- [ ] RAG 知识库有租户隔离与来源校验，检索片段过护栏（LLM08）
- [ ] API 层限流、配额、异常消耗告警（LLM10）
- [ ] 用户数据进入训练/日志前脱敏，提供退出选项（LLM02/04）
- [ ] 微调数据与模型文件来自可信来源并校验完整性（LLM03/04）
- [ ] 生成内容接入内容标识；上线前完成安全评估（合规）

## 小结

- OWASP LLM Top 10（2025）是应用层安全风险的权威清单：注入、泄露、供应链、投毒、输出处理、代理、提示词泄露、向量弱点、错误信息、无限制消耗。
- 提示注入无法被 RAG/微调根除，缓解靠纵深防御：约束行为、格式校验、输入输出过滤、最小特权、人工审批、内容隔离。
- NeMo Guardrails 给出工程化的护栏实现：输入/对话/检索/执行/输出五类 rails，包住 LLM 的每个出入口。
- 合规是部署的一部分：内容标识、数据合法性与安全评估不因"模型是开源的"而豁免。
