## 引言：并行编码智能体的生活方式

> 以下摘译自 Simon Willison。

一段时间以来，我不断听说有工程师同时运行多个编码智能体——同时开好几个 Claude Code 或 Codex CLI 实例，有时在同一个仓库，有时对着多个 checkout 或 git worktree。

我起初相当怀疑。AI 生成的代码需要审查，这意味着整件事的天然瓶颈是**我审查的速度**。光是跟上单个 LLM 的产出就已经很吃力，多开几个只会让我落得更远，那图什么？

尽管疑虑重重，过去几周我发现自己悄悄拥抱了并行编码智能体的生活方式。我可以专注审查并落地**一个**重要改动，但越来越多任务可以在并行轨道上发出，而不给我主业增加太多认知负担。我总结出的适用模式：

- **概念验证型研究**：回答问题、给出建议、不产生要保留的修改。库太新不在训练数据里？没关系——让智能体 checkout 依赖仓库、读源码搞清用法。
- **"这里怎么实现的来着？"**：让智能体讲清系统某部分的工作原理——签名 cookie 在哪设置和读取、JSON API 哪些端点没写进文档。产出的解释值得存起来，是未来提示词的好上下文。
- **小型维护任务**：测试套件在报弃用警告？扔给一个智能体："跑测试套件，想出修法。"这类小刺激不值得打断你的主业。
- **规格明确的正事**：从天而降的代码审起来最贵——你得先反推它的目标、判断方案优劣。**从你自己的规格出发的代码**，审起来省力得多。

## Agent Teams：会话编队

> 以下为 Claude Code 官方文档译文。

> **警告**：Agent teams 为实验性功能，默认关闭。在 settings.json 或环境变量中设置 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 启用。它围绕会话恢复、任务协调、关闭行为存在已知限制。

Agent teams 让你编排多个 Claude Code 实例协同工作：一个会话担任**队长（team lead）**，负责协调、分派任务、综合结果；**队友（teammates）**各自拥有独立上下文窗口独立工作，并且**彼此直接通信**。你也可以越过队长直接与任何队友对话。

组队之前先想想更轻的选项够不够用：子智能体（subagents）在单个会话内拆分工作；跨会话消息让你手动管理的会话互通发现。

### 什么时候用 agent teams

并行探索真正增值的任务最适用：

- **研究与审查**：多个队友同时调查问题的不同侧面，互相分享并质疑发现
- **新模块或新功能**：每人负责一块互不踩脚
- **竞争假设调试**：各测一个理论，更快收敛答案
- **跨层协调**：改动横跨前端、后端、测试，各由一个队友负责

Agent teams 有协调开销、token 消耗显著高于单会话。队友能独立运作时效果最好；顺序任务、同文件编辑、依赖繁重的工作，单会话或子智能体更划算。

### 与子智能体对比

**表：子智能体 vs Agent Teams**

| | 子智能体 | Agent Teams |
| --- | --- | --- |
| 上下文 | 独立窗口；结果回传调用方 | 独立窗口；完全独立 |
| 通信 | 把结果返回调用方（具名子智能体也可互发消息） | 队友直接互发消息 |
| 协调 | 主智能体管理全部工作 | 自协调：消息 + 共享任务列表 |
| 适合 | 只关心结果的聚焦任务 | 需要讨论与协作的复杂工作 |
| token 成本 | 较低（结果摘要回主上下文） | 较高（每个队友都是独立实例） |

要快速聚焦、汇报即走，用子智能体；要队友互相分享发现、互相挑战、自组织协调，用 agent teams。

### 启动你的第一个智能体编队

启用后用自然语言描述任务与想要的队友即可。下面的例子效果好，因为三个角色相互独立、无需互相等待：

```text
I'm designing a CLI tool that helps developers track TODO comments across
their codebase. Spawn three teammates to explore this from different angles:
one on UX, one on technical architecture, one playing devil's advocate.
```

（译：我在设计一个帮开发者跟踪代码库中 TODO 注释的 CLI 工具。派三个队友从不同角度探索：一个管 UX，一个管技术架构，一个唱反调。）

Claude 随后填充共享任务列表、为每个视角派生队友、让它们探索问题、最后综合发现。队长的终端在输入框下方的智能体面板里列出队友：上下箭头选中、回车查看其记录并直接发消息、Esc 清除选择（查看其记录时 Esc 打断该队友当前轮次）。

### 控制你的编队

- **计划先行**：可以让队友在实现前先制定计划供审批（"Have teammates plan before implementing"），复杂工作建议开启。
- **显示模式**：in-process（全部队友跑在主终端内）或 split panes（每个队友一个窗格，需 tmux 或 iTerm2）。
- **直接对话**：通过面板可以不经过队长直接对任何队友说话。

### 分派与认领任务

共享任务列表协调整队工作，任务有 pending / in progress / completed 三态，并支持**依赖关系**——有未解决依赖的 pending 任务在依赖完成前不可认领。分派有两种：

- **队长指派**：告诉队长哪个任务给哪个队友
- **自主认领**：队友完成一个任务后，自己捡起下一个未指派、未阻塞的任务

任务认领用文件锁防止多个队友同时抢同一个任务的竞态。

### 用 hooks 强制质量闸门

队友收工或任务创建/完成时可用 hooks 介入：`TeammateIdle`（队友将转入空闲时运行，以退出码 2 发送反馈并让它继续干）、`TaskCreated`（可阻止任务创建）、`TaskCompleted`（可阻止标记完成）。

### 架构

**表：Agent Team 的组成**

| 组件 | 角色 |
| --- | --- |
| Team lead | 派生队友、协调工作的主会话 |
| Teammates | 各自处理分派任务的独立 Claude Code 实例 |
| Task list | 队友认领与完成的共享工作项列表 |
| Mailbox | 智能体间通信系统 |

每个智能体的邮箱是 `~/.claude/teams/{team-name}/inboxes/{agent-name}.json` 文件；只有写入收件人邮箱成功，消息才算发出。任务依赖自动管理：队友完成被依赖任务时，下游任务自动解锁。团队与任务存储在会话派生名下（`session-` + 会话 ID 前 8 字符）；会话结束团队配置目录自动清理，任务列表本地保留供恢复会话使用、永不上传。

### 权限与消息安全

队友继承队长的权限模式（dontAsk 模式除外）；队友的权限提示出现在队长会话中，由你批准。**智能体间消息**有明确的安全语义：接收方会被告知消息来自另一个 Claude 会话而非你；队友不能替你批准权限或代为同意；被拒绝某操作的队友也不能把操作转包给另一个队友绕过检查。auto mode 的分类器把其他智能体转来的"批准声明"当作不可信输入，并在投递前审查每条消息——被拦截的消息不会到达收件人。

### 上下文与 token

每个队友有自己的上下文窗口：派生时加载与普通会话相同的项目上下文（CLAUDE.md、MCP 服务器、skills），外加队长的派生提示；**队长的对话历史不带入**。队友之间通过自动消息投递、空闲通知（附最终答案）、共享任务列表、按名点名通信共享信息。

token 消耗随活跃队友数线性放大：研究、审查、新功能开发的额外 token 通常值得；例行任务用单会话更划算。

### 用例示例

- **并行代码审查**：三个队友分别从正确性、安全、性能三个维度审同一 diff，队长汇总去重
- **竞争假设调查**：一个性能问题让每个队友验证一个假设，最先证实的结论胜出

### 最佳实践

- **给队友足够的上下文**：派生提示里写清目标、约束、接口约定——队友看不到队长的对话历史
- **选择合适的团队规模**：不是越多越好；超过 3-5 人协调成本开始反噬
- **任务粒度适当**：太大无法并行，太小协调开销占大头
- **等待队友完成再综合**：别在队友还在工作时频繁催促
- **从研究与审查开始**：第一次组队拿低风险任务练手
- **避免文件冲突**：按文件边界切分任务，或给每个队友配 git worktree（见第 13 篇）

> 译注：多智能体协作的三条适用判据——任务可独立切分、结果可验证、协调收益大于协调成本。三条都不满足时，请回到第 7 篇的"单个 Claude + 子智能体"基线。Agent teams 与模块 9《多智能体模式》（LangGraph 编排）是同一思想在不同层的实现：一个编排 IDE 里的会话，一个编排运行时的状态机。
