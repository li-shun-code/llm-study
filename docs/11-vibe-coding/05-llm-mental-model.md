上一篇你完成了第一次 AI 结对，但有一个问题值得在任何进阶工作流之前回答：当你按下回车，AI 到底"看"到了什么？它并不是打开了你的编辑器——它看到的是一个叫**上下文窗口**的 token 序列。本篇主体翻译 Claude Code 官方文档《How Claude Code works》（智能体循环与访问边界）与《Explore the context window》（上下文构成），并在文末补一节分词（tokenization）对编码的影响。建立这套心智模型，后面第 6 篇的工作流、第 14 篇的上下文工程才有着力点。

## 一、智能体循环（The agentic loop）

*以下译自官方文档 [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)。*

当你给 Claude 一个任务，它按三个阶段工作：**收集上下文（gather context）→ 采取行动（take action）→ 验证结果（verify results）**。三个阶段相互交融：Claude 全程使用工具——搜索文件理解你的代码、编辑做出修改、运行测试检查工作。

循环会适应你的请求：关于代码库的提问可能只需要收集上下文；修 Bug 会让三个阶段反复循环；重构可能涉及大量验证。Claude 根据上一步学到的东西决定下一步，把几十个动作串起来并随时纠偏。

**你也是循环的一部分。**你可以在任何时刻打断 Claude，把它引向另一个方向、补充上下文或要求换一种方法。Claude 自主工作，但对你的输入保持响应。

智能体循环由两个组件驱动：负责推理的**模型（model）**与负责行动的**工具（tool）**。Claude Code 充当围绕 Claude 的**智能体鞍架（agentic harness）**：提供工具、上下文管理与执行环境，把一个语言模型变成能干活的编码智能体。

### 模型

Claude Code 使用 Claude 模型理解代码与推理任务。Claude 能读任何语言的代码、理解组件如何连接、弄清要达成目标需要改什么。复杂任务会被拆成步骤执行，并根据所学调整。多档模型各有取舍：Sonnet 擅长大多数编码任务，Opus 为复杂架构决策提供更强推理——会话中用 `/model` 切换，或以 `claude --model <name>` 启动。本文说"Claude 选择/决定"时，指的都是模型在做推理。

### 工具

没有工具，Claude 只能输出文本；有了工具，它能行动：读代码、改文件、跑命令、搜网页、调外部服务。每次工具调用的结果都会回流进循环，影响下一个决策。内置工具大致分五类：

| 类别 | 能做什么 |
| --- | --- |
| **文件操作** | 读文件、改代码、新建文件、重命名与重组 |
| **搜索** | 按模式找文件、用正则搜内容、探索代码库 |
| **执行** | 跑 shell 命令、启动服务、跑测试、用 git |
| **Web** | 搜索网页、抓文档、查错误信息 |
| **代码智能** | 编辑后看到类型错误与警告、跳转定义、找引用（需代码智能插件） |

比如你说"fix the failing tests"，Claude 可能：跑测试看哪些失败 → 读错误输出 → 搜相关源文件 → 读文件理解代码 → 编辑修复 → 再跑测试验证。每次工具调用都给它新的信息， inform下一步——这就是智能体循环的运转方式。

## 二、Claude 能访问什么

在某个目录运行 `claude` 后，Claude Code 获得对以下内容的访问：

- **你的项目**：目录与子目录中的文件；其他位置需你授权
- **你的终端**：你能从命令行做的一切——构建工具、git、包管理器、系统工具、脚本
- **你的 git 状态**：当前分支、未提交改动、近期提交历史
- **你的 CLAUDE.md**：存放项目级指令、约定与上下文的 Markdown 文件，每次会话都会加载
- **自动记忆（auto memory）**：Claude 在工作中自动保存的心得（如你的偏好），MEMORY.md 的前 200 行或 25KB 在每次会话开始时加载
- **你配置的扩展**：MCP 服务器（外部服务）、技能（工作流）、子智能体（委托工作）、Chrome 集成（浏览器交互）

正因为 Claude 看到的是整个项目，它能跨文件工作：让 Claude "修认证 Bug"，它会搜相关文件、读多个文件建立上下文、跨文件协同修改、跑测试验证、按需提交——这与只看当前文件的行内补全助手是两个物种。

## 三、上下文窗口：一切的成本中心

*本节主体译自同页 "The context window" 及 "When context fills up" 小节。*

Claude 的上下文窗口容纳：对话历史、文件内容、命令输出、CLAUDE.md、自动记忆、已加载技能与系统指令。随着工作推进，上下文逐渐填满。Claude 会自动压缩（compact），但对话早期的指令可能丢失。**把持久规则写进 CLAUDE.md，别依赖对话历史**；用 `/context` 查看空间占用。

### 当上下文填满时

接近上限时，Claude Code 自动管理上下文：先清掉较旧的工具输出，必要时再总结对话。你的请求与关键代码片段会被保留，对话早期的详细指令可能丢失。要控制压缩时保留什么，可在 CLAUDE.md 加"Compact Instructions"一节，或带焦点运行 `/compact`（如 `/compact focus on the API changes`）。

如果某个文件或工具输出大到"每次压缩后立刻重新填满"，Claude Code 会在几次尝试后停止自动压缩并报错（官方排障页称 thrashing error）。此外，MCP 工具定义默认延迟加载（tool search），只有工具名与服务器说明占用上下文，具体 schema 到用的时候才载入。

### 用技能与子智能体管理上下文

除压缩外还有两个阀门：**技能（Skills）**按需加载——会话开始只看到一行行技能描述，正文用到才加载；**子智能体（subagents）**在各自独立的上下文窗口工作，其工具调用不占你的上下文，结束时只交回一份总结。这两个机制分别在后面第 11 篇与第 6/20 篇展开，但它们存在的理由现在就清楚了：**上下文是稀缺资源**。

## 四、一次会话启动时，上下文里到底装了什么

*以下事实译自官方交互演示页 [Explore the context window](https://code.claude.com/docs/en/context-window)（以 200K token 上下文为例，数字为演示值）。*

- **系统提示词**（约 4200 token）：行为、工具使用与响应格式的核心指令，永远最先加载，你从来看不到它
- **自动记忆 MEMORY.md**（约 680 token）：Claude 写给自己的笔记——它学到的构建命令、注意到的模式、要避免的错误；前 200 行或 25KB 加载
- **环境信息**（约 280 token）：工作目录、平台、shell、OS 版本、是否 git 仓库；git 分支/状态/近期提交作为独立块挂在系统提示词最末
- **MCP 工具（延迟）**（约 120 token）：只列工具名，完整 schema 按需加载
- **技能描述**（约 450 token）：每个技能一行描述；正文用到才加载，且这一节在 `/compact` 后不会自动重建，只有你真正调用过的技能会被保留

也就是说：**在你打出第一句话之前，上下文已经预装了约 5-6K token 的"世界观"**。你读进来的每个文件、每条命令输出都在这 200K 里占位——"LLM 如何看你的代码"的答案就是：它通过工具把你的代码搬进这个窗口，而窗口会被塞满、被压缩、被策略性地腾空。

## 五、分词：LLM 眼中没有"字符"（本站编者补充）

*本节为本站编者补充。tokenizer 的系统讲解见模块 4《LLM 基础》的分词器篇章，这里只说它对日常编码的三个直接影响。*

1. **token 是计价与限额单位，不是字符也不是词**。一个英文单词约 1-1.5 个 token，一个中文汉字约 1-2 个 token，而一段压缩后的 JSON、一行长 import、一个长 Base64 串可能动辄几十上百 token。这就是为什么第 24 篇的成本管理盯着"命令输出与文件读取"——它们按 token 计费地灌进上下文。
2. **标识符会被切成奇怪的碎片**。`getUserAccountBalance` 在模型眼里可能被切成 `get|User|Account|Balance`，而拼写错误 `getUsreAccountBalence` 切片完全不同。两个形态相近的变量名在 token 层面可能距离很远——这是"AI 有时认不出两处'长得一样'的代码"的原因之一。写提示词时给出精确的标识符原文（复制粘贴而非口述）能显著提升命中率。
3. **精确字符串匹配（grep）仍是底层工具**。理解了上面两点，就明白为什么 Claude Code 这类工具内置 Grep/精确搜索而非"语义查找"——先用确定性工具锁定位置，再让模型阅读理解，比让模型全库"感觉"更省 token 也更可靠（第 6 篇最佳实践中的"先探索再动手"正是这个道理）。

## 六、两种保险丝：检查点与权限

同页官方还概述了两道安全机制，这里一并译出作为后面两篇的引子：

- **检查点（checkpoints）**：文件编辑可回滚。Claude 编辑文件前会先快照当前内容；出问题时按两次 `Esc` 回到之前的状态，或直接让它撤销。检查点独立于 git，恢复会话后依然可用；只覆盖文件改动，远程系统操作（数据库、API、部署）不在其列。
- **权限（permissions）**：按模式设定 Claude 不问你的许可就能做什么——**Auto**（分类器后台审查、拦截高危动作）、**Manual**（改文件与跑命令前先问）、**Accept edits**（直接改文件、跑常见文件系统命令）、**Plan**（只探索并给出计划，不动源文件）。也可以在 `.claude/settings.json` 里放行特定命令。
